Status: **normative spec for four parallel work packages** ("core", "wiring", "server", "ui"), 2026-10-05.
If this document and a skeleton docstring disagree, this document wins. Do not edit this file while

The student's request, verbatim: "can you build a bot that tracks the polymarket and kalshi markets for the
markets on the competition and the bot flags when any of those markets experience a significant movement
since it seems the markets on susquehanna are delayed".

## 0. Goal and hard rules

**Goal.** Watch the Polymarket and Kalshi markets already matched to Cup outcomes about every 15 s, flag
significant outside moves, compare each with the Cup at the same moment, tell the student whether the Cup
is lagging (and what hand trade that suggests), and **measure** whether the Cup really is delayed (how often
and how fast it follows), so the student can decide with numbers, not a hunch.

**Hard rules (a reviewer rejects any change that breaks one).**

* **Read-only, GET only, everywhere.** Outside hosts are read only through the fair-value providers'
  `readonly.outside_client` (anonymous, GET/HEAD, no redirects). The Cup is read only through the
  tracker's single-attempt client (guarded by `readonly.enforce_get_only`). Nothing places, cancels or
  simulates an order. The alert view, the CLI and the JSON say "suggestion only" next to every trade.
  `moves.py` joins the static AST scan of `tests/test_readonly.py` with **no** allowlist entry. That scan
  flags any call to an attribute named `post`, `put`, `patch`, `delete`, `send`, `stream`, `build_request` or
  `mint_realtime_token` (so no `queue.put(...)` or `generator.send(...)` either), any `.request(` whose first
  argument is not the literal "GET"/"HEAD", any `method=` other than GET/HEAD, `httpx.Request(...)`, and the
  string literals "POST", "PUT", "PATCH", "DELETE" or anything containing "/orders".
* **Never touch the Super Market budget for outside tracking.** Outside polls use each provider's own
  per-host limiter (§4.3). The only Cup reads this feature adds are optional order-book reads for lagging
  alerts (≤ 4 per minute, behind the read reserve, skipped and never waited for, §13.4).
* **No look-ahead.** Every outside sample carries the time its batch's response **arrived** (stamped on
  completion, lookahead-2); every Cup snapshot the tracker's completion time; a decision at `t` uses only
  data with a time `<= t`. An alert's `detected_at` is the clock read after every poll of the step returned.
* **Honest.** An outside price can be wrong or thin; a gap may persist until resolution; a move the Cup has
  not followed is not a guaranteed profit; no text calls an alert a sure thing. Small samples say so in a
  fixed sentence. Demo results carry `MOVES_DEMO_CAVEAT`.
* **Independent of the paper trader.** Alerts never change the simulator's inputs, its portfolios or its
  pre-registered verdict (§24 M12): the paper results the student will judge stay comparable.
* **Python 3.9+**, no new runtime dependencies (httpx only), offline tests only.
* **Backward compatible.** Existing endpoints keep every key (new keys are additive); the default demo
  (`build_demo()` without `moves=True`) is byte-for-byte the demo of today; `paper --demo --fast` output is
  unchanged; schema migration v2 -> v3 keeps all data.

   web/ (ui):       "Outside moves" view, nav badge, optional beep and desktop notifications

## 3. Conventions and shared types

* Times are epoch seconds (UTC floats) from the injected clock; ISO only at the edges.
* Prices are **YES probabilities** in [0, 1]. A "point" is 0.01 (1 percentage point): a move of 0.05 is
  "+5.0 pts". The Cup tick is 0.005 (`depth.TICK`); buy limits use `depth.floor_tick`.
* `direction` (`d`) is +1 when the YES price rose, -1 when it fell. A move's size `M` is always positive:
  `M = d x (after - before)`.
* "Buy NO at q" = "sell YES at 1 - q" (docs/PAPER_TRADING.md §3). NO ask = 1 - YES bid.
* Every dataclass has `to_dict()` (`models._Serializable`); JSON is that output.

## 4. Outside polling (core: `fairvalue.py`)

### 4.1 `poll(targets, now, *, deadline=None) -> ProviderResult` (both providers)

A quote-only read of the matches the last `refresh` **validated** (`self._matches`, keyed by exchange id)
for the given targets (skip `disabled` targets and targets without a validated match on this venue). It
never reads an unvalidated pin and never runs discovery or validation: matching stays the fair-value
refresh's job (fail closed, D50). Before the first refresh validated anything it returns
`ProviderResult(status="pending", requests=0, errors=["No validated <Label> match yet: waiting for the first
fair-value refresh."])`.

* **Polymarket:** `GET {base}/markets?id=<id1>&id=<id2>...&limit=<n>` with at most
  `POLYMARKET_IDS_PER_CALL` (50) ids per call (`limit` = number of ids, exactly like `refresh`, so the D57
  mock rule matches the same fixtures). A bare JSON array.
* **Kalshi:** `GET {base}/markets?tickers=<t1,t2,...>&limit=100`, at most `KALSHI_TICKERS_PER_CALL` (100)
  tickers per call; the base-URL fallback of §4.5 applies (once per poll, on a connect error only).
* **Parsing:** the provider's existing `_quote(market, match, fetched)` (same fields, flags, placeholder
  rules), so a polled quote equals a refreshed one for the same JSON. `ProviderResult.liquidity[eid] =
  liquidityNum` (Polymarket, a number or numeric string; absent: not set); Kalshi sizes stay on the quote
  (`bid_size` / `ask_size` from `yes_bid_size_fp` / `yes_ask_size_fp`).
* **Light checks** per returned market (cheap, no network): Polymarket `active is True`, `closed is False`,
  `outcomes == ["Yes", "No"]`; Kalshi `status in {"active", "open"}`. A market that fails is **not quoted**
  and gets `rejected[eid]` = one sentence ("Polymarket market 630844 is closed: not polled."); its match is
  kept (the next refresh decides). A requested id the venue did not return is simply not quoted.
* **Stamping (lookahead-2):** `fetched = self._clock()` is read right after **that batch's** response arrived
  and was parsed; every quote of the batch gets `fetched_at = fetched`. Never the request start, never the
  venue's `updatedAt` / `updated_time` (those stay `venue_updated_at`, informational).
* `result.matches[eid]` = a copy of the polled match; `result.requests` = calls made by this poll.

### 4.2 Shared state, locking, failures

* `_HttpVenue` gains `self._io_lock = threading.Lock()`. `refresh` takes it **blocking** for its whole
  duration; `poll` waits at most `MOVES_POLL_LOCK_WAIT_S` (3 s) and otherwise returns
  `ProviderResult(status="busy", requests=0)` (the fair-value refresh is reading the same host right now;
  the watcher simply has no new sample for that venue this step). No other lock is held while either runs.
* `poll` shares `_begin` / `_finish` with `refresh`: one host, one backoff. A 429 seen by either sets
  `_next_try_at = now + min(Retry-After, MAX_RETRY_AFTER_S=600)` (else the `BACKOFF_S` step); during the
  backoff both return early without a request ("backoff", or "offline" with the real cause first, live-4).
  The first connect error, proxy refusal, DNS failure or timeout ends the poll at once ("offline"), exactly
  like §4.4 of PAPER_TRADING.md. A successful poll resets the failure count, like a successful refresh.
* **Deadline:** the watcher passes `deadline = <provider start> + MOVES_POLL_DEADLINE_S` (10 s); no batch
  starts after it (status "partial", error "<Label> poll stopped at the 10 s deadline: some outcomes were not
  read this time."). One black-holed host therefore costs at most ~18 s (10 s + one 8-s timeout).
* **Headroom:** a batch starts only while its host limiter has at least `MOVES_POLL_HEADROOM + 1` (9) free
  slots (`limit - used >= 9`); otherwise the poll ends "partial" with "<Label>'s per-minute budget is kept for
  the fair-value refresh: some outcomes were not polled." The 60-s fair-value refresh therefore never loses
  a refresh to the watcher (it needs <= 5 calls on Polymarket, <= 3 on Kalshi, plus <= 3 discovery pages).
* `budget() -> {"used": int, "limit": int}`: the host limiters' `used` summed, and `reads_per_min`.
* `poll` never raises except `ReadOnlyViolation` (an unexpected exception becomes status "error" with
  "<Label> data could not be read (<Type>): no outside quotes from <Label> this time.").

| Host | poll (every 15 s) | fair-value refresh (every 60 s) | discovery (every 6 h at most) | steady per minute | limiter |
|---|---|---|---|---|---|
| `gamma-api.polymarket.com` | ceil(231/50) = 5 calls -> 20/min | 5/min | <= 3 pages | **25** (28 in a discovery minute) | 45/min |

## 5. Series, volatility and thresholds (core)

### 5.1 Samples and series

`sample_from_quote(eid, quote, liquidity=)` -> `OutsideSample(ts=quote.fetched_at, bid, ask, value, spread,
bid_size, ask_size, liquidity, flags, external_id, match_kind, match_confidence)` with `value` = the mid when
`0 < bid < ask < 1` and `ask - bid <= 0.10` (`fairvalue.MAX_VENUE_SPREAD`), else **None** (a last-trade-only,
placeholder or one-sided quote is never a move sample; see the `placeholder` filter of §6.2). `is_thin(sample)`
adds the flag "thin" when the spread exceeds `MOVES_MAX_SPREAD` (0.05), or Polymarket `liquidity <
MOVES_MIN_LIQUIDITY_USD` (5,000), or a known touch size (`bid_size` or `ask_size`) `< MOVES_MIN_TOP_SIZE` (100).

`SeriesBuffer(eid, venue)` keeps, per (outcome, venue): raw samples for `MOVES_RAW_KEEP_S` (75 min: the 60-min
window, its 15-min base tolerance and the confirmation) and **minute bars** for `MOVES_VOL_LOOKBACK_S` (6 h):
`minute_bars(samples, start, end)` = the last sample value of each minute, forward-filled while the last
sample is at most `MOVES_BAR_FILL_S` (360 s) old, else None. Memory target < 40 MB for 237 outcomes x 2
venues (keep bars compact, e.g. one `array('d')` per series with a start minute; raw samples as tuples).
Samples older than or equal to the series' newest `ts` are ignored (no reordering).

### 5.2 Volatility `sigma(W)`

`window_sigma(bars, bar_start, W, now)` = `sqrt(mean(clip(bar(t) - bar(t - W), -0.10, +0.10)^2))` over every
minute `t` in `[now - 6 h, now - W - 60]` with both bars present (the move under test and the minute before it
never set their own bar). Fewer than `MOVES_VOL_MIN_PAIRS` (30) pairs -> **None** (unknown). Never below
`MOVES_VOL_FLOOR` (0.005). Cached per series and window, recomputed at most every `MOVES_VOL_REFRESH_S`
(300 s). Pure-function check: bars `[0.50, 0.50, 0.51, 0.51, 0.50, 0.52]` one minute apart, W = 60 s,
`vol_min_pairs = 5`: changes 0, +0.01, 0, -0.01, +0.02 -> mean square 1.2e-4 -> sigma = 0.01095.

### 5.3 Thresholds

`threshold_for(W, sigma)` = `max(MOVES_ABS_MIN[W], MOVES_K_SIGMA x sigma)` when sigma is known, else
`MOVES_ABS_MIN[W] x MOVES_WARMUP_FACTOR` (1.5; the "warm-up thresholds" flag).

| W | minimum | why the minimum | warm-up | example sigma -> threshold |
|---|---|---|---|---|
| 60 s | 0.03 | a 3-pt jump in a minute is news-sized; below it a typical Cup spread (2-4 pts) plus the venues' half-spreads eat it | 0.045 | 0.003 -> 0.03; 0.010 -> 0.040 |
| 300 s | 0.04 | the shortest window a human can still act on | 0.06 | 0.006 -> 0.04; 0.013 -> 0.052 |
| 900 s | 0.05 | | 0.075 | 0.010 -> 0.05; 0.016 -> 0.064 |
| 3600 s | 0.07 | an hour of drift on a toss-up race is commonly 1-3 pts | 0.105 | 0.015 -> 0.07; 0.030 -> 0.12 |

K = 4 because every outcome is evaluated over 4 windows x 2 venues every 15 s: overlapping evaluations are
correlated, but at 3 sigma a fat-tailed quiet series would still produce several false alerts a day across
237 outcomes; the debounce (§7) collapses repeats, the minimum keeps quiet series honest.

## 6. Move detection (core)

### 6.1 One venue over one window: `evaluate_window(series, now, W)`

1. **Base**: the samples with `ts` in `[now - W - tol, now - W]`, `tol = max(2 x poll_s, 0.25 x W)` (30 s at
   W = 60 with a 15-s poll; 900 s at W = 3600); `base_value` = the median of the up to 3 latest of them,
   `base_ts` = the latest of them. None in the band -> not evaluable (return None).
2. **Confirmation**: the last `MOVES_CONFIRM_SAMPLES` (2) samples with `ts > base_ts`; they must be at least
   `MOVES_CONFIRM_MIN_SPAN_S` (10 s) apart and both have a value. `d` = sign(latest - base). The
   conservative `after_value` = the confirming sample nearest the base in direction `d` (the min of the two
   for an up move, the max for a down move); `move = after_value - base_value`.
3. **Freshness**: the latest sample older than `stale_s = max(3 x poll_s, 45 s)` -> `stale = True`; two
   consecutive samples in `[base_ts, now]` more than `gap_s = max(3 x poll_s, 60 s)` apart -> `gap = True`.
4. **Thin**: `thin = True` when the base sample or either confirming sample is thin (§5.1).
5. `threshold = threshold_for(W, series.sigma(W, now))`, `ratio = |move| / threshold`.

Worked example (W = 60, poll 15 s, sigma(60) = 0.003 known -> threshold 0.03). Samples (seconds, value):
0: 0.520, 15: 0.520, 30: 0.521, 45: 0.519, 60: 0.540, 75: 0.580, 90: 0.578.
At `now = 90`: base band [0, 30] -> median(0.520, 0.520, 0.521) = 0.520, base_ts = 30; confirming 75 and 90
-> after = min(0.580, 0.578) = 0.578; move = +0.058, ratio 1.93 -> triggers. At `now = 75`: confirming 60
and 75 -> after = 0.540, move +0.020, ratio 0.67 -> no trigger (one sample alone is never enough). The
outside half-way time (for the lag) interpolates on the samples: half of 0.058 is reached at 0.549, between
60 (0.540) and 75 (0.580): `t_move = 60 + 15 x 0.009 / 0.040 = 63.4 s`.

### 6.2 Filters (each dropped would-be alert becomes a `SuppressedMove` with its reason)

A venue's window move is **usable** only when evaluable, not `stale`, not `gap`, not `thin`, its samples
have values, its `match_kind` is EXACT (or NEAR with the target's `trade_near`) and its
`match_confidence >= 0.8`. Reasons, in the order they are checked (the first one that applies is reported):

| reason | when | example sentence (`detail`) |
|---|---|---|
| `placeholder` | the venue's latest quote has no value (one-sided, placeholder, last-trade-only, wider than 0.10) while its last valued sample would have triggered | "Kalshi's quote turned one-sided: not a price." |
| `match` | match confidence < 0.8 | "Discovered match with confidence 0.75: too uncertain to alert on." |
| `near` | NEAR match and not `trade_near` (chamber control, Independent legs) | "Near match (different settlement wording): not alerted." |
| `stale` | `stale` or `gap` | "Polymarket was not read for 2.5 min inside this window." |
| `thin` | `thin` | "Demo venue A's book was 10 pts wide during the move." |
| `single_tick` | the previous step's latest sample alone exceeded the threshold and the current latest is back under half of it | "One print of +9.0 pts that did not hold." |
| `disagree` | two usable venues, one with ratio >= 1, the other with ratio < `MOVES_CONFIRM_FRACTION` (0.5) in the same direction, or moving the other way | "Polymarket +6.0 pts, Kalshi +1.0 pt: the venues disagree." |
| `suspect` | not `confirmed` and `|outside now - Cup mid now| > 0.25` | "Outside 0.86 vs Cup 0.42: check the match." |
| `no_cup` | no Cup snapshot within `MOVES_CUP_MAX_AGE_S` (120 s) of now | "No Cup price in the last 2 minutes to compare with." |

A filtered venue does not count either way (it neither alerts, confirms nor disagrees). The same
(outcome, reason) suppressed again within `MOVES_SUPPRESS_REPEAT_S` (300 s) counts once. `summary()` keeps the
latest `MOVES_MAX_SUPPRESSED_SHOWN` (20) and per-reason counts for the last 24 h.

### 6.3 Combining venues: `combine_venues(eid, W, moves)`

* **Two usable venues** A and B: trigger when both moved the same direction, `mean(ratio_A, ratio_B) >= 1`
  and `min(ratio_A, ratio_B) >= 0.5` -> `confirmation = "two venues"`. Otherwise, if one has `ratio >= 1` ->
  suppressed `disagree`.
* **One usable venue** (the other unmatched, filtered, offline or stale): trigger when `ratio >= 1` ->
  `confirmation = "one venue"`, flag "one venue".
* The `CombinedMove` (`venues` in provider order: polymarket, kalshi | demo-a, demo-b): `before` / `after` /
  `now` = means over the confirming venues; `move` = `d x (after -
  before)`; `t_base` = the latest `base_ts`; `t_move` = the mean of the venues' half-way times; `threshold` =
  the largest venue threshold; `sigma` / `vol_known` from that venue; `uncertainty` = `max(|A_now - B_now|`
  (0 with one venue)`, the tightest half-spread, the largest MOVES_FEE_BAND of the venues)`.

Worked example ("Example L", W = 300 s, North Carolina Senate D). Polymarket base 0.520 -> after 0.580,
spread 0.01, liquidity 210,000, sigma(300) = 0.008 -> threshold max(0.04, 0.032) = 0.04, move +0.060, ratio 1.50.
Kalshi base 0.515 -> after 0.565, spread 0.02, sizes 900 / 1,400, sigma 0.011 -> threshold max(0.04, 0.044) =
0.044, move +0.050, ratio 1.14. Mean ratio 1.32 >= 1, min 1.14 >= 0.5 -> triggers: before 0.5175, after 0.5725,
M = 0.055, threshold 0.044, uncertainty max(0.015, 0.005, 0.02) = 0.02. Disagreement variant: Kalshi +0.01
(ratio 0.23): mean 0.86 < 1, Polymarket alone has ratio 1.5 -> suppressed `disagree`.

When several windows trigger in one step, the **shortest** is the alert's `window_s`; all are listed in
`windows`.

## 7. Alerts: debounce and lifecycle (core)

* **One open alert per outcome.** `alert_id = f"mv-{eid}-{int(t_base)}"` (deterministic). A trigger in the
  alert's direction while it is open **updates** it: `windows` and `venues` gain members,
  `peak_move = max(peak_move, d x (outside_now - outside_before))`, `grown_at` = now when the peak rose by
  `MOVES_GROWTH_STEP` (one tick) or more. The base (`t_base`, `outside_before`) never changes.
* A trigger in the **other** direction while an alert is open: the open alert is first checked for reversion
  (§10.1); if it reverted it closes, and the new trigger opens a new alert when its `t_base >= old.grown_at`
  (a distinct move); otherwise the opposite trigger is ignored until the old alert resolves.
* **Re-arm**: after an alert closed, a new alert in the same direction needs `t_base >= old.grown_at`, so one
  move never produces a second alert.
* **Linking**: an alert opened within `MOVES_LINK_S` (120 s) of an open alert on another leg of the same
  `race_key` is linked both ways (`linked`).
* **Close**: an alert closes (`state = "closed"`, `closed_at`) when its lag outcome is resolved (or it is not
  lag-eligible) and nothing grew for `MOVES_CLOSE_QUIET_S` (300 s); a not-followed one closes when its
  `MOVES_LAG_TRACK_S` (60 min) end. Closed alerts still receive `capture_4m` / `exit_30m` until they are known
  (at most `240 + 1800` s after detection) and are re-persisted then.
* **Events** (to listeners and alerts.jsonl): `opened` (creation), `status` (a change of `status` or of
  `lag.outcome`), `closed`. Number updates (a growing peak, a new trade limit) are not events.
* Each step re-computes for every open alert: `outside_now`, `cup_now`, `lag_gap_now = peak_move - d x (Cup now
  - Cup at base)`, `level_gap_now = d x (outside_now - Cup mid now)`, the trade (§9) and `actionable = state
  == "open" and status == "lagging" and trade is not None`.

## 8. Comparing with the Cup, and classification (core)

### 8.1 The Cup series

The watcher keeps the Cup snapshots of every target for 2 h (deduplicated by `ts`; from `CupFeed.quotes()`
each step and, once at the first step, `CupFeed.history(7200)`). `cup_at(series, t)` = the latest snapshot
with `ts <= t` and `ts >= t - 120 s`, else None. `mid` is the two-sided mid, else the mark; a Cup spread
wider than 0.10 adds the flag "wide Cup book".

### 8.2 `classify(move, cup_series, now)` -> (status, reason, CupContext, exclusion)

With `base = cup_at(t_base)`, `ref = cup_at(t_base - 900 s)` (if there is none, the earliest snapshot at or
before `t_base`, flag "short Cup history"), `now_q = cup_at(now)`:

1. `now_q` None -> the move is suppressed `no_cup` (no alert).
2. **Cup moved first**: `move_lookback = d x (now_q.mid - ref.mid) >= 0.5 x M`, and the Cup's half-way time
   `half_cross_ts` (the first of 2 consecutive snapshots after `ref` with `d x (mid - ref.mid) >= 0.5 x M`) is
   at least `MOVES_CUP_FIRST_MARGIN_S` (60 s) before `move.t_move` -> `moved_first`; lag outcome `cup_first`
   (resolved now, `lag_s = half_cross_ts - t_move`, negative).
3. **Converging** (the outside moved to where the Cup already was): `level = d x (move.now - now_q.mid) <
   MOVES_CONVERGE_FRACTION x M` (0.5) and the Cup did not move half-way over the window -> `already_moved`,
   lag **excluded** (`excluded_reason` "converging: the outside moved to the Cup's price").
4. **Cup already moved**: `move_same_window = d x (now_q.mid - base.mid) >= 0.5 x M` -> `already_moved`; the
   lag outcome resolves as `followed` once the follow rule (§10.1) finds its confirmed half-way snapshot
   (`lag_after_alert_s` may be <= 0).
5. Otherwise -> **`lagging`**.

`lag_gap = M - move_same_window` (points of the move not yet in the Cup; larger than M when the Cup moved the
other way).

Reason sentences (exact templates; numbers in points with one decimal, prices with 3 decimals):

| status | reason |
|---|---|
| lagging | "The outside price moved {+5.5} pts in {5 min}; the Cup has moved {+0.0} pts over the same time (now {0.512})." |
| already_moved (Cup moved) | "The Cup has already moved {+3.0} of the {5.5} pts (now {0.545}): no edge left to chase." |
| already_moved (converging) | "The outside price moved to where the Cup already was ({0.575}): no edge." |
| moved_first | "The Cup moved {+3.5} pts about {11 min} before the outside price: the outside followed the Cup, not a lag." |
| reverted | "The outside price came back {3.5} of its {5.5} pts before the Cup moved." |
| lagging, not followed (closed) | "The Cup did not follow within 60 min; the gap is {6.0} pts now." |

Worked examples (Example L of §6.3: d = +1, before 0.5175, now 0.5725, M = 0.055, t_base 14:00:00, t_move
14:02:40, detection 14:05:15):

* **lagging**: Cup bid 0.505 / ask 0.52 (mid 0.5125) at t_base, at t_base - 15 min and now -> move_same_window
  0, move_lookback 0, level 0.5725 - 0.5125 = 0.06 >= 0.0275 -> lagging; lag_gap = 0.055.
* **already_moved**: Cup now mid 0.545 (+0.0325 >= 0.0275 since the base).
* **moved_first**: the Cup rose 0.515 -> 0.55 between 13:50 and 13:53, half-way (0.5425) confirmed at 13:51:30;
  the outside's half-way time 14:02:40 is 670 s later (>= 60) -> moved_first, lag_s = -670.
* **converging**: Cup mid 0.575 throughout: level 0.5725 - 0.575 = -0.0025 < 0.0275 -> already_moved, excluded.

## 9. The hand trade (core): `hand_trade(d, outside_values, u, cup, book, book_source, now)`

Only for `lagging` alerts. Side: d = +1 -> buy YES; d = -1 -> buy NO.

* Conservative outside value of the side: `v = min(outside_values)` for YES, `1 - max(outside_values)` for NO
  (the confirming venues' latest values).
* `h` = Cup half-spread `(ask - bid) / 2` (no two-sided Cup quote -> no trade, "The Cup has no two-sided quote
  right now.").
* `limit` = the side's best ask now: YES ask, or `1 - YES bid` for NO; from the book when it is at most
  `MOVES_BOOK_MAX_AGE_S` (120 s) old and newer than the snapshot, else from the snapshot; on the tick.
* `edge_per_share = v - h - limit` (you buy at the ask; if the Cup's mid catches up to `v` you sell at its bid);
  `edge_after_uncertainty = edge_per_share - u`; `edge_at_resolution = v - limit` (you hold to the end and the
  outside price is right).
* `max_limit = depth.floor_tick(v - h - u - MOVES_MIN_EDGE)`; if `limit > max_limit` -> no trade, trade_note
  "The Cup's ask ({0.535}) leaves less than 1 cent per share after the spread and the outside price's
  uncertainty: no trade suggested." (the status stays `lagging`, not actionable).
* Depth from the book (`depth.contract_levels(bids, asks, side, "buy")`): `shares_at_limit` =
  `depth.available(levels, limit, buy=True)`, `shares_to_max` = `depth.available(levels, max_limit, True)`;
  no fresh book -> both None and the text says so.
* `text` = "Buy YES at 0.520" / "Buy NO at 0.430"; `note` = `MOVES_TRADE_NOTE`.

Worked example (Example L, lagging): v = min(0.580, 0.565) = 0.565; u = 0.02; Cup bid 0.505 / ask 0.52 -> h =
0.0075, limit 0.520. edge_per_share = 0.565 - 0.0075 - 0.520 = **0.0375**; after uncertainty **0.0175**; at
resolution **0.045**. max_limit = floor_tick(0.565 - 0.0075 - 0.02 - 0.01 = 0.5275) = **0.525**. Book asks
[(0.52, 300), (0.525, 450), (0.53, 800)] -> 300 shares at 0.520, 750 up to 0.525. NO-side example (demo
"lead_long", d = -1): outside 0.58 -> 0.52 (venues 0.52 and 0.525 -> v = 1 - 0.525 = 0.475), u = 0.005, Cup bid
0.57 / ask 0.59 (h 0.01): limit = 1 - 0.57 = 0.430, edge 0.475 - 0.01 - 0.43 = 0.035, after u 0.030, max_limit =
floor_tick(0.45) = 0.450, shares at 0.430 = the YES bid's size at 0.57.

Book reads: when an alert becomes lagging, and while it stays lagging every 120 s, the watcher first takes
`CupFeed.stored_book(eid)` if it is at most 120 s old (`book_source = "stored"`), else asks
`CupFeed.book(eid)` once (`"read"`; None when there is no budget room: shares stay unknown).

## 10. Lag measurement (core)

### 10.1 `update_lag(alert, cup_series, outside_points, now)` (each step, every alert with work left)

Eligible alerts are every alert except converging ones and those without a Cup base snapshot (excluded).

* **Followed**: scanning Cup snapshots after `t_base` (in order), the first run of `MOVES_FOLLOW_CONFIRM` (2)
  consecutive snapshots with `d x (mid - cup_base.mid) >= 0.5 x peak_move` (the peak at that time) ->
  `followed_at` = the run's first `ts`, `lag_s = followed_at - t_move`, `lag_after_alert_s = followed_at -
  detected_at`. A lagging alert that followed changes status to `already_moved` (event "status").
* **Reverted** (only while pending): 2 consecutive outside points (the mean of the confirming venues at each
  poll after detection) with `d x (v - outside_before) <= (1 - 0.5) x peak_move` -> outcome `reverted`, status
  `reverted`. When a follow and a reversion fall in the same step, the earlier time wins.
* **Not followed**: `now - t_move >= MOVES_LAG_TRACK_S` (3600 s) while pending.
* **Censored** (excluded from the shares, counted): the watcher had a gap longer than `MOVES_RESUME_GAP_S`
  (600 s) while the alert was pending (restart, stall), its outcome left the targets (closed / settled), or no
  Cup snapshot for 600 s. Reason sentences: "The bot was not running for 25 min while this was measured."
  / "The market closed before the Cup followed." / "No Cup price for 10 min."
* **Captures** (alerts that were lagging at detection): at `now >= detected_at + 240` (`t_h`):
  `capture_4m = d x (outside(t_h) - cup(t_h).mid) - cup(t_h).spread` (outside(t_h) = the confirming venues'
  mean at the latest poll at or before t_h); at `now >= t_h + 1800`: `exit_30m` = buy the side at its ask at
  `t_h`, sell at its bid at `t_h + 1800` (YES: `bid(t_e) - ask(t_h)`; NO: `bid(t_h) - ask(t_e)`). Missing data ->
  None. These are per share, net of the spread, with no impact or queue: an upper bound for a hand trade.

Worked lag (Example L): Cup snapshots 14:05:30 0.5125, 14:06:00 0.520, 14:06:30 0.530, 14:07:00 0.545,
14:07:30 0.550. Half of the peak 0.055 is 0.0275 -> 14:07:00 (+0.0325) and 14:07:30 (+0.0375) confirm ->
followed_at 14:07:00, lag_s = 14:07:00 - 14:02:40 = **260 s**, lag_after_alert_s = **105 s**. Capture at
14:09:15 (Cup 14:09:00 bid 0.55 / ask 0.56, outside 0.5725): 0.5725 - 0.555 - 0.01 = **+0.0075**. Exit at
14:39:15 (Cup 14:39:00 bid 0.565): 0.565 - 0.56 = **+0.005** per share.

### 10.2 `summarise(alerts, now)` -> `LagSummary`

Over every stored alert dict (up to 30 days): `moves` = eligible alerts; `races` = their distinct race keys;
`resolved` = outcome not pending/censored; `outside_led = resolved - cup_first`; shares are of `outside_led`
(None when 0):

* `followed_within[k]` for k in 60/300/900/3600 s: followed with `lag_s <= k` (counts in `followed_within_n`);
* `never_followed = reverted + not_followed` with its share, and both parts with theirs;
* `cup_first_share` = cup_first / resolved;
* `median_lag_s`, `median_lag_after_alert_s`, `lag_quartiles_s` over followed alerts;
* `capture_4m`, `exit_30m`: `{"n", "mean", "median", "positive_share", "ci90"}` over alerts with a value; `ci90`
  = a t-interval over **per-race means** (races share news and national swings) with `n_races - 1` df when
  `n_races >= MOVES_CI_MIN_RACES` (5), else None;
* `small_sample = outside_led < MOVES_MIN_SAMPLE (20) or races < MOVES_MIN_RACES (10)`;
* `sentence`: `MOVES_NO_DATA_SENTENCE` when `moves == 0`; `MOVES_SMALL_SAMPLE_SENTENCE` when small (n =
  outside_led + cup_first, followed, never, cup_first, min_n 20, min_races 10); else
  `MOVES_SUMMARY_SENTENCE` with shares as whole percents ("41%"), durations as "3.5 min" (under 1 min: "40 s"),
  money per share signed with 3 decimals ("+0.008"), "n/a" for a missing value.

Example: 46 outside-led moves on 21 races, followed within 5 min 19, within 60 min 33, median lag 210 s (90 s
after the alert), capture mean +0.004 (n = 40), exit mean -0.002 (n = 37) -> "Over 46 outside moves on 21
races, the Cup followed within 5 minutes 41% of the time and within an hour 72%; the median lag was 3.5 min
after the outside move (1.5 min after the alert). Acting 4 minutes after an alert left an average gap of
+0.004 per share net of the spread (n=40); buying then and selling 30 minutes later averaged -0.002 per share
(n=37). Moves cluster on news days and races share national swings, so treat this as a hint, not proof."

## 11. Persistence, alerts.jsonl and restart

* **Samples**: a sample is persisted when its series' value, bid or ask moved by at least
  `MOVES_QUOTE_RECORD_MIN_CHANGE` (0.005) or its flags changed since the last stored sample, or
  `MOVES_QUOTE_HEARTBEAT_S` (300 s) passed (`persistence.add_outside_quotes(rows)`, rows =
  `OutsideSample.to_dict()`). Expected live volume: ~350k rows/day (~35 MB), kept 3 days.
* **Alerts**: every created or changed alert (including number updates and late captures) is upserted at the
  end of the step (`put_move_alerts`, rows = `MoveAlert.to_dict()`).
* **alerts.jsonl** (`data/<slug>/alerts.jsonl`; demo `<data dir>/demo/alerts.jsonl`): one line per event,
  `{"event": "opened"|"status"|"closed", "at": <epoch>, "at_iso": "2026-10-05T14:05:15Z", "alert":
  MoveAlert.to_dict()}`, opened in append mode, flushed per step, never truncated or rewritten. An I/O error is
  logged once per hour and shown as the watcher's `last_error`; tracking continues.
* **Warm-up and restart** (first step): load alerts detected in the last 30 days (`move_alerts(since=now -
  30 d)`), samples of the last 6 h (`outside_quotes(since=now - 6 h)`; series rebuilt, bars forward-filled per
  §5.1) and the Cup history (2 h). `gap = now - max(newest stored sample ts, newest open alert updated_at)`;
  when `gap > MOVES_RESUME_GAP_S` (600 s) every pending lag is censored ("The bot was not running for {25} min
  while this was measured.") and its alert closes; otherwise open alerts continue with the same ids, the same
  base and the same lag state. Restarting never re-opens a closed alert and never writes a second "opened"
  line for the same alert.

## 12. The watcher (core): API and threading

### 12.1 Construction

`OutsideMoveWatcher(fair_values, *, providers=None, cup=None, persistence=None, alerts_path=None,
clock=time.time, params=None, demo=False)`: see the skeleton docstring. `fair_values.mode` must be "auto"
(the builders never build a watcher otherwise). `providers=None` uses `fair_values.providers`.

### 12.2 `step(now=None) -> MovesStepReport` (never raises except ReadOnlyViolation / BaseException)

1. First step only: warm-up (§11).
2. `targets = fair_values.targets()`; active = not disabled. (No lock held.)
3. For each provider with a `poll`: `res = provider.poll(active, clock(), deadline=clock() + 10)`; exceptions
   become status "error". (No lock held; providers serialise themselves.)
4. `cup = cup_feed.quotes()` (no lock held).
5. `now_eval = clock()` (after every poll returned; `now` given by a synchronous caller is only a lower bound:
   `now_eval = max(now, clock())`).
6. **Under the watcher lock** (pure computation only): ingest samples with `ts <= now_eval`, ingest the Cup
   snapshots; evaluate every target (§6); open / update alerts (§7, §8); list the alerts that need a book;
   update every lag (§10.1); collect events and rows to persist.
7. Book reads outside the lock (§9), at most as many as `CupFeed.book` grants.
8. Under the lock again: attach books, recompute trades and `actionable`; build and **publish** the new
   `summary()` and `status()` dicts (replace the references, never mutate published dicts).
9. Outside the lock: persist, append alerts.jsonl, call listeners (each exception logged and ignored).

### 12.3 Lock rule (extends D43)

The watcher lock is a **leaf**: no other lock is taken while it is held, and it is never held while calling
the FairValueService, a provider, the Cup feed (the tracker), the persistence (the store), the file or a
listener. The tracker never calls the watcher while holding `tracker._lock`; `tracker.status()` and the web
handlers read `watcher.status()` / `watcher.summary()` lock-free. Providers' I/O locks are taken only inside
`refresh` / `poll`. Lock order overall: runner -> FairValueService -> tracker (unchanged); provider I/O lock and
the watcher lock are independent leaves.

### 12.4 Published dicts

`summary()` is the §18.2 body without `now`, `enabled`, `available`, `error`, `demo`, `book_reads` (web.py adds
those). `status()`: `{"enabled": true, "poll_s", "last_step_at", "steps", "open", "actionable",
"actionable_alerts": [{"alert_id", "exchange_id", "headline", "body", "detected_at"}] (<= 10, newest first),
"venues": {"ok": int, "total": int}, "last_error": str|null}` where `headline, body =
notification_text(alert)` (§19.4) and "ok" counts venues whose last poll status is ok or partial.

## 13. Tracker integration (wiring)

### 13.1 Constructor and threads

`Tracker(..., moves=None, moves_reads_per_min=MOVES_READS_PER_MIN)` (skeleton stores them). When `moves` is
given: `moves.bind(TrackerCupFeed(self))`; `self.moves_budget = MovesBudget(SlidingWindowLimiter(
moves_reads_per_min, clock=self._limiter_clock, sleep=self._limiter_sleep) if moves_reads_per_min > 0 else None,
self.read_reserve)`; `start()` adds the thread `tracker-moves` running `_moves_worker`: `next = monotonic();
loop: moves_step(); resolve/record the problem; next += moves.poll_s (skip missed slots); wait(next - now)`.

### 13.2 `TrackerCupFeed` and the published quotes

* `_publish(now, rows)` adds `"quotes": {eid: {"ts", "bid", "ask", "mid", "last", "spread"}}` for every
  non-stale row (ts = the row's `updated_at`, i.e. the snapshot read's completion); `cup_quotes()` returns them
  as `moves.CupQuote`s, lock-free.
* `cup_history(seconds)` copies `(ts, bid, ask)` of tick points of `self._series` newer than `now - seconds`
  under `self._lock` (briefly) and builds `CupQuote`s outside it.
* `TrackerCupFeed.quotes()` / `.history()` delegate; `.stored_book(eid)` returns the store's newest book for
  the outcome as a `BookObservation` (`store.book(eid)`: `{"at", "bids", "asks"}`), or None; `.book(eid)`:
  return None when `moves_budget.room() <= 0`; else `acquire()`, `tracker._quick.get_exchange_orderbook(eid,
  depth=20, tournament_id=...)` -> `BookObservation(eid, observed_at=clock(), bids, asks, source="moves")`;
  **not** stored (M12); a `SuperMarketError` -> `tracker._api_error("outside-move order book for exchange
  <eid>", exc, MOVES_PROBLEM)` and None.

### 13.3 Synchronous methods and status

* `moves_step(now=None)`: None without a watcher; else `report = self.moves.step(now)`; set or resolve the
  `MOVES_PROBLEM` problem from `moves.status()["last_error"]`; return the report. Never under `self._lock`.
* `moves_view()`: `self.moves.summary()` or None.
* `status()` adds `"moves": self.moves.status()` (or None) and `read_budget["moves"] =
  self.moves_budget.status()` (or None). `PROBLEM_SEVERITY[MOVES_PROBLEM] = "warning"`.
* The §9 projection adds `moves_reads_per_min` when a watcher is configured (its worst case).

### 13.4 `MovesBudget`

`room() = min(own.limit - own.used, reserve.room())` (0 when `own` is None); `acquire()` = `own.acquire()`
(callers check `room()` first, so it never waits); `status()` = `{"used", "limit", "room"}` (limit 0 when
disabled). Fast demo: the builders pass `FAST_READS_PER_MIN` so a SimClock run never stalls.

+/-0.005 to bid and ask on about a quarter of 15-s buckets (hash of seed, eid, bucket); prices rounded to 0.001.

## 16. `pipeline.run_simulation(..., moves_every_s=None)` (wiring)

When `moves_every_s` is given and `runtime.tracker.moves` is not None: at each step, after the paper step,
`tracker.moves_step(now)`; then for every sub-tick `t = step_time + j x moves_every_s` strictly before the next
step time: `clock.set(t)`, `tracker.moves_step(t)`; the next step then advances the clock to its own time
(so a step still moves the clock by `step_s` in all, and the first moves step runs at the demo start).
`moves_every_s=None` keeps the loop byte-for-byte as before (the paper tests' determinism, D42). Two fast runs
give identical `/api/moves` bodies.

### 17.2 Output (exact formats; `moves.format_event_lines` / `moves.summary_lines`, core)

Formatting rules (core, used by every line below): points `f"{x * 100:+.1f} pts"` (signed) or `f"{x * 100:.1f}
pts"`; prices `f"{p:.3f}"`; per-share money `f"{x:+.3f}"`; durations `f"{s:.0f} s"` under 60 s, `f"{s / 60:.1f}
min"` under an hour, else `f"{s / 3600:.1f} h"`; windows "1 min" / "5 min" / "15 min" / "1 h"; times `HH:MM:SS`
UTC. First line of every event: `f"[moves {hhmmss}] {TAG}  {race_label}  {title}"` (`title` = the Cup title, `+
" — " + option` when the option is not YES/None). TAGs: opened -> `CUP LAGGING` | `CUP ALREADY MOVED` | `CUP MOVED
FIRST`; status events -> `FOLLOWED` | `REVERTED` | `NOT FOLLOWED` | `CENSORED` (and `CUP ALREADY MOVED` when a lagging
alert's status changes without a follow, e.g. converging later). `closed` events print nothing in text mode (they
are in alerts.jsonl and `--json`). Detail lines are indented four spaces.

Start: "Watching outside prices: Polymarket and Kalshi every 15 s for 231 matched outcomes (GET only, no
account). Alerts also go to data/<slug>/alerts.jsonl. Nothing is traded. Ctrl-C to stop." (demo: "Watching the
demo's scripted outside venues (Demo venue A, Demo venue B) every 15 s. Demo data: the moves are scripted.
Nothing is traded.")

Events (times UTC `HH:MM:SS`; `<label>` = race label; title and option as on the Cup; "\a" appended to the first
line when `--bell` and the alert is actionable when opened):

```
[moves 14:05:15] CUP LAGGING   North Carolina Senate (D)  Will the Democratic Party win the North Carolina Senate?
    outside 0.517 -> 0.573 (+5.5 pts in 5 min; Polymarket, Kalshi); Cup 0.512 (bid 0.505 / ask 0.520), +0.0 pts; lag gap 5.5 pts
    suggestion (not a sure thing): Buy YES at 0.520, 300 shares at that price (750 up to 0.525); +0.037/share net of the spread, +0.018 after the outside price's uncertainty
[moves 14:07:30] FOLLOWED  North Carolina Senate (D)  Will the Democratic Party win the North Carolina Senate?
    the Cup moved +3.2 pts, 4.3 min after the outside move (1.8 min after the alert)
[moves 13:51:40] CUP MOVED FIRST  Minnesota Senate (D)  Will the Democratic Party win the Minnesota Senate?
    the Cup moved +4.5 pts about 3.8 min before the outside price: the outside followed the Cup, not a lag
[moves 13:52:10] CUP ALREADY MOVED  Ohio Senate (R)  Will the Republican Party win the Ohio Senate?
    the Cup has already moved -3.0 of the 6.0 pts (now 0.550): no edge left to chase
[moves 14:13:45] REVERTED  Pennsylvania Governor (R)  Will the Republican Party win the Pennsylvania Governor?
    the outside price came back 4.5 of its 6.0 pts before the Cup moved
[moves 15:04:15] NOT FOLLOWED  Wisconsin Governor (D)  Will the Democratic Party win the Wisconsin Governor?
    the Cup did not follow within 60 min; the gap is 7.0 pts now
[moves 15:20:00] CENSORED  New Hampshire Senate (D)  Will the Democratic Party win the New Hampshire Senate?
    the bot was not running for 25 min while this was measured
```

(The detail line of a status event is its `reason` / `lag.reason` sentence with the first letter lower-cased
and the final period dropped.)

A lagging alert without a suggestion prints "    no trade suggested: <trade_note>" as its third line; an
unknown depth prints "shares at that price unknown (no recent Cup order book)". `--only-lagging` prints only
alerts that were lagging when opened and their later lines. Summary (every `--summary-every` minutes and at the
end): `[moves 14:20:00] summary: <LagSummary.sentence>` then `    venues: Polymarket ok (231 matched, 25/45 reads
a minute); Kalshi offline (Kalshi is unreachable from this machine (could not connect): ...)` and
`    filtered out today: 3 thin or wide outside book, 1 the other venue did not move`; the final block adds the
caveats (one per line, "  - ") and, for the demo, `MOVES_DEMO_CAVEAT`. `--json`: one JSON object per line instead,
`{"type": "event", "event": kind, "alert": {...}}`, `{"type": "summary", "summary": {...}, "venues": [...]}`.

Exit codes: 0 ok, 2 usage / config / lease conflict, 1 API or OS error, 130 Ctrl-C (after printing the final
block).

## 24. Design decisions

**M1. Poll the validated matches, do not re-match.** The 60-s fair-value refresh already validates pins live and
fails closed (D50); a fast path that read pins directly would bypass that. `poll` reads only `self._matches`,
so an outcome is watched only after it passed validation, and a pin that fails a later refresh stops being
polled.

**M2. One provider object, one host budget, one backoff.** The watcher calls the same provider instances the
fair-value service uses, so a 429 from either path pauses both (Retry-After capped at 600 s), the first offline
error is reported once, and the per-host numbers of §4.3 are what the host really sees. An I/O lock serialises
the two paths; the poll skips ("busy") rather than queueing behind a 38-s worst-case refresh.

**M3. The fair-value refresh keeps its cadence and its semantics.** Raising it to 15 s would have changed
`prev_value` (the D18 jump check), the fair-value records the backtest replays (D24) and the paper results the
student is about to judge. The poll is separate and quote-only; the 60-s refresh is untouched, with guaranteed
headroom (M2, §4.2).

**M4. Stamp on arrival, evaluate after arrival.** Gamma has no quote time; Kalshi's `updated_time` is not a
quote time either. Each batch's quotes carry the clock read after the response, and a step evaluates at the
clock read after every poll (lookahead-2). The consequence for the lag (an outside move may be up to one poll
earlier than stamped; Gamma may itself lag its order book) biases the measured Cup lag DOWN (the Cup looks
faster), the conservative direction for "the Cup is delayed"; caveat 4 says so.

**M5. Two thresholds, both required.** An absolute minimum per window (3-7 points, below which a hand trade
cannot clear the Cup spread) AND K = 4 of the outcome's own recent outside volatility (a usually jumpy longshot
needs a bigger move). A warm-up factor of 1.5 applies until 30 minute-pairs of history exist, so a fresh start
is stricter, not looser.

**M6. Noise filters fail quiet and are shown.** Thin or wide books, single prints, venue disagreement, NEAR and
suspect matches, stale or interrupted quotes, placeholders, low match confidence and missing Cup prices each drop
an alert with a named reason, counted and listed in "Filtered out", so the student can see what was not alerted
and why instead of trusting a silent filter.

**M7. One move, one alert.** One open alert per outcome, updated in place (peak, windows, venues, trade); a fixed
base; re-arming only after the move stopped growing. Events are emitted only on open, status change and close,
so the CLI and notifications do not repeat.

**M8. "Cup moved first" looks back 15 minutes.** Comparing only the same window would call a move the Cup made 4
minutes earlier "lagging" (the demo's cup_first scenario). The 900-s look-back with a 60-s margin separates the
two; converging moves (the outside moving to the Cup's price) are not lag observations and are excluded.

**M9. A trade only with an edge after costs and doubt.** The suggested limit is the side's current ask, accepted
only if the outside value (the more conservative venue) minus the Cup half-spread minus the outside uncertainty
(venue disagreement, half-spread, fee band) still leaves 1 cent; depth from a real book only, else "unknown";
every suggestion carries `MOVES_TRADE_NOTE`.

**M10. Measure the lag the way the student would trade it.** "Followed" needs half the move, the same way, on two
consecutive Cup snapshots (a one-snapshot blip does not count); the lag is reported from the outside move AND from
the alert; captures are measured at alert + 4 minutes (`HUMAN_LATENCY_S`, D7) net of the spread, and a 30-minute
hold is reported too. Censored and converging moves are counted but excluded. The interval is over per-race means
(D2's lesson: races share news), and below 20 moves or 10 races the fixed sentence says the sample is too small.

**M11. Persist what is needed to survive a restart, not a full tape.** Samples on a one-tick change plus a 300-s
heartbeat (about 35 MB a day, 3 days), every alert with its lag state (30 days), and an append-only alerts.jsonl
for the student's own records. A restart within 10 minutes continues open alerts; a longer gap censors them
rather than inventing what happened while the bot was down.

**M12. Alerts do not change the simulator.** The paper trader's verdict is pre-registered (D4) and fingerprinted
(D49); a new signal source mid-run would invalidate both. Alerts therefore feed the value ideas only as
annotations (`outside_move` on /api/strategy, `move` on /api/fairvalue rows), the watcher's Cup book reads are not
stored where ideas read books, the demo's moves venues are not fair-value providers, and the `paper` command never
runs the watcher. The lag study (with its 4-minute capture and 30-minute exit) is the evidence about trading alerts
by hand; a future "move" idea kind would need its own pre-registered paper test.

**M13. Demo scenarios that exercise every branch, without disturbing the paper demo.** Seven extra markets exist
only with `outside_moves=True`; their Cup moves stay below the surge detector's thresholds; two scripted venues
make "two venues", "one venue only" and "disagree" visible; the script repeats hourly with the direction flipped,
so a long dashboard demo keeps producing believable alerts and the odd cycles show converging moves.

**M14. Notifications and sound are opt-in and CSP-clean.** Off by default, enabled by a click (the browser
requires a gesture for both), no inline code, textContent only; the first poll after a page load never beeps or
notifies for alerts that were already open.

## 26. Integration notes (after the four packages merged)

Changes the integrator made on top of §1-§25, each for honesty or consistency; the tests named below pin them.

* **Races are counted over the same moves as the numbers they qualify** (`summarise`). `LagSummary.races` counts the
  races of the *resolved* alerts (the `n` of the small-sample sentence), and the new optional field
  `outside_led_races` counts the races of the outside-led ones; `small_sample` and the full sentence use
  `outside_led_races`. Before, pending alerts counted as races, so "Only 4 outside moves on 5 races" could appear,
  and pending alerts on new races could lift a sample over the 10-race bar. (`test_moves.py::
  test_summarise_counts_races_over_the_same_moves_as_its_numbers`)
* **Sentences read right for one move or none resolved.** `MOVES_SMALL_SAMPLE_SENTENCE` takes `{moves_word}` /
  `{races_word}` ("1 outside move on 1 race"); with alerts but none resolved yet the summary says
  `MOVES_PENDING_SENTENCE` ("No outside move has been resolved yet (1 still being measured): far too few ...")
  instead of "Only 0 outside moves on 1 races".
* **Captures never use a stale Cup price in their favour** (`update_lag`). The Cup is sampled once per tracker
  interval (30 s), so the snapshot at or before `t_h` can predate a catch-up already under way. `capture_4m` waits for
  the first Cup snapshot after `t_h` (or `MOVES_CUP_MAX_AGE_S`) and takes the less favourable of the two;
  `exit_30m` buys at the worse ask around `t_h` and sells at the worse bid around `t_e`. Closed alerts keep
  receiving captures for `cup_max_age_s` longer. (`test_update_lag_captures_take_the_less_favourable_bracketing_cup_snapshot`)
* **A seventh caveat** in `MOVES_CAVEATS`: the Cup is read once per snapshot interval, so a measured lag can be up to
  one interval longer than the real one (the opposite bias of caveat 4) and "followed within 1 min" is rough.
* **The `moves` command's final block and `--replay` print the lag numbers with their sample sizes**
  (`moves.lag_table_lines`): followed within 1/5/15/60 min as k/n, never followed with its parts, the median lag, and
  the 4-minute gap and the 30-minute hand trade with n, the share positive and the 90% interval (or why there is
  none). The sentence alone hides them on a small sample.
* **The replay uses the stored opening suggestion** (`MoveAlert.opened_trade`): without alerts.jsonl it no longer
  says the suggestion "was not kept"; that line remains only for rows stored without `opened_trade`. alerts.jsonl's
  *last* "opened" line of an id wins (the file is append-only across fresh demo databases).
* **The Outside moves card says the current level gap** ("the outside price is now 6.0 pts above the Cup") next to
  the peak-based lag gap when they differ by half a point or more (a partly reverted outside price, or prices that
  started apart), so the headline number never overstates what a trade can still use; the trade box already
  priced against the current outside value.
* **A move that is not a lag shows no lag gap.** A "Cup moved first" alert and a converging "Cup already moved" one
  (the outside price moved to the Cup's price) say "no lag gap: ..." and the current price gap instead of a peak-based
  "lag gap 6.3 pts" that would read like an open opportunity.
* **The replay does not claim nothing was filtered**: suppressed moves are not stored, so `moves --replay` says
  "filtered out: not kept in the database" instead of "filtered out today: nothing".
* `HandTrade.book_age_s` is never negative (a book read just after the evaluation time).
* The moves-related `pytest.skip` guards that waited for the server package are removed: a regression now fails.
