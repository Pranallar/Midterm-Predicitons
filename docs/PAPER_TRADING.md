## 0. Goal, and the rules that bind every package

**The user's goal.** A student in the Susquehanna Predictions Cup (Super Market platform, 2026
midterms, virtual SUSQies, 100,000 start, Cup ends 2026-11-04T17:00:00Z, only the top 3 are paid,
final rank = SUSQies balance after every market resolves) is behind and wants "the most
profitable strategy", and wants the bot to **simulate it for a day on live read-only data** before
they act on it. So we build:

1. **Outside fair value** (A): Polymarket, Kalshi and a user-editable file, matched to every Cup
   outcome. This is the largest legitimate edge the research found; the bot had none.
2. **New idea kinds and goal-based sizing** (B): `value` (Cup price vs fair value), `basket`
   (pair/set arbitrage, including the NO basket when YES bids sum above 1), `hole` (deep resting
   orders that catch liquidity holes), the existing fade/carry/arbitrage with their wrong
   assumptions fixed, and a `chaser` sizing policy next to the conservative one.
3. **A paper trader** (C): several simulated portfolios on the live signals with a conservative
   fill model, liquidation-value marks, and an honest verdict after the run; plus a **backtest**
   that replays stored history through the same code.
4. **Integration** (E): the tracker runs fair value and the paper trader in budgeted workers; new
   JSON endpoints; `paper`, `backtest` and `fairvalue` commands; demo scenarios so all of it is
   testable offline and the demo shows a believable simulation within minutes.
5. **A Simulation view** (F) in the dashboard.

**Hard rules (a reviewer will reject any change that breaks one).**

* **Strictly read-only.** No new code may call any Super Market order or write endpoint
  (`POST/PUT/PATCH/DELETE` anything, `/orders*`, cancel-all, multi-leg, `POST /realtime/token`).
  New Super Market reads are only: `GET /exchanges/{id}/orderbook`, `GET /exchanges/{id}/trades`,
  `GET /tournaments/{slug}/markets?status=settled`, `GET /tournaments/{slug}/leaderboard?limit=100`
  (all through the existing `SuperMarketClient`). Outside hosts are read with `GET` only
  (Polymarket Gamma, Kalshi v2; never Polymarket's batch POSTs). The paper trader books simulated
  orders and fills **locally**. `tests/test_readonly.py` proves it (§7.8). The only POST routes are
  the dashboard's own local ones (`/api/surges/<id>/analyze`, new `/api/paper/reset`), which touch
  nothing outside this process.
* **No rule-breaking strategies.** No manipulation (no pushing thin prices or the closing VWAP,
  no spoofing), no multi-accounting, no collusion or value transfer, no wash trading. Ideas trade
  on public information, structure (prices that do not add up) and passive liquidity provision.
  Copy for the UI says so where relevant.
* **Honest results.** No look-ahead (a decision at `t` uses data stamped `<= t`; a fill uses an
  observation made after the decision); conservative fills (real depth, no re-use of liquidity
  already taken, latency, trade-through for passive orders); liquidation-value marks as the
  headline; explicit statistical uncertainty and "not enough evidence yet" below thresholds;
  demo results labelled as scripted.
* **Python 3.9+** (`from __future__ import annotations`, `typing.List/Dict/Optional`, no `match`,
  no `X | Y` at runtime). No new runtime dependencies (`httpx` only). Offline tests only (no
  network in the test suite).
* **Backward compatible JSON.** Existing endpoint shapes keep every key; new keys are additive.

## 1. Architecture

```
                        +------------------------- Tracker (tracker.py, E) ---------------------------+
 Super Market API  <--- | tracker-loop      every 30 s: market list, bulk prices -> ticks, surges, view |
 (GET only, 90/min      | tracker-context   every 300 s: constraints, balance, leaderboard(100),        |
  client limiter)       |                   idea/overround books, settlements (600 s)                   |
                        | tracker-backfill / tracker-analysis   (unchanged)                              |
                        | tracker-paper     after each cycle: PaperRunner.step()  [own 20 reads/min]     |
                        +-----------------------------------------------^---------------------------------+
 Polymarket / Kalshi <--- tracker-fairvalue every 60 s: FairValueService.refresh()   | (fairvalue.py, A)
 (GET only, own budget)                                                               |
                                                                                      |
   PaperRunner.step (paper.py, C)  =  run_step(engine, inputs, obs, fulfil):          |
     inputs, obs = pipeline.assemble_inputs + pipeline.observation   (E, no reads) ---+
     plan        = engine.wanted_reads(...)            books/tape this step needs
     fulfil      = TrackerMarketReader.book / .trades (E)  <= 8 books + 2 tapes / step
     signals     = strategy.generate_signals(inputs)   (B)  value/basket/hole/fade/carry/arbitrage
     engine.step = fills -> settlements -> marks -> exits -> entries (sized by sizing.py, B) -> equity
                   persisted in SQLite (store.py v2, E)

   backtest.run_backtest (C) = the same run_step over HistoricalMarket (stored ticks, candles,
                               fair values, book snapshots, tape), with a look-ahead guard.

   web.py (E): /api/paper, /api/paper/reset (POST), /api/backtest, /api/fairvalue, + /api/strategy
   web/ (F):   Simulation view, Strategy view additions
```

Threads never block the snapshot loop: fair value and paper each run in their own worker; a
failing outside host or a slow paper step only shows up as a problem in `/api/status`.

## 3. Conventions and shared types

* **Times** are epoch seconds (UTC floats). ISO only at the edges.
* **YES price vs contract price.** Books, quotes and the tape are YES prices. Orders, fills,
  positions and trades are in **contract prices**: the price of the contract named by `side`
  (`"yes"`: YES price; `"no"`: `1 - YES price`). Buying NO at `q` = selling YES at `1 - q`.
  For a YES best bid `b` and ask `a`: NO ask = `1 - b`, NO bid = `1 - a`.
* **Units** are shares for single-outcome ideas and *sets* (one share of every leg) for set
  ideas (`unit == "sets"`, kinds in `SET_KINDS`).
* **Tick** = 0.005. `floor_tick(x) = floor(x / 0.005 + 1e-9) * 0.005`, `ceil_tick` likewise,
  results rounded to 3 decimals. Prices must lie in [0.005, 0.995] for orders.
* **Money** is SUSQies; round displayed money to 2 decimals, never round internal accounting.
* **Serialisation**: every dataclass has `to_dict()` (via `models._Serializable`); sets become
  sorted lists, NaN becomes null. Endpoints return `to_dict()` output plus the extra keys of §10.
* **Errors**: providers, the runner and the services never raise on bad data; they report.
  Only shutdown (`tracker._Stopping`) and fatal key errors propagate (existing tracker rules).

### 4.1 Race-key normaliser

`parse_race(title, option=None) -> Optional[RaceRef]`:

| Title (and option) | RaceRef |
|---|---|
| `Will the Democratic Party win the New Hampshire Senate?` | `2026:SENATE:NH`, office SENATE, state NH, party D |
| `Will the Republican Party win the Georgia Governor?` | `2026:GOVERNOR:GA`, R |
| `Will the Democratic Party win the AZ-01 House race?` | `2026:HOUSE:AZ-01`, office HOUSE, state AZ, district `AZ-01`, D |
| `Will the Independent Party win the Nebraska Senate?` | `2026:SENATE:NE`, I |
| `Will the Democratic Party win the U.S. Senate?` | `2026:SENATE_CONTROL:US`, D |
| `Will the Republican Party win the U.S. House?` | `2026:HOUSE_CONTROL:US`, R |
| `Will Democrats win the Michigan Senate race?` (demo) | `2026:SENATE:MI`, D |
| `Will Republicans win Ohio House District 9?` (demo) | `2026:HOUSE:OH-09`, R |
| `Which party will control the Senate after the midterms?` + option `Republicans` | `2026:SENATE_CONTROL:US`, R, source "option" |
| `Which party will control the House after the midterms?` + `Democrats` | `2026:HOUSE_CONTROL:US`, D, source "option" |
| `Who will win the Arizona Governor race?` + `Any other candidate` | `2026:GOVERNOR:AZ`, O, source "option" |
| `Will Republicans keep control of the Pennsylvania Senate?` | None (a state chamber) |
| `How many House seats will Democrats win?`, `Will a Libertarian candidate win a U.S. House seat?`, debate markets | None |

Rules: regexes `CUP_TITLE_RE`, `HOUSE_RACE_RE`, `LEGACY_TITLE_RE`, `LEGACY_DISTRICT_RE` in the
skeleton; state names via `STATE_CODES` (exact, case-sensitive full names; "U.S." handled
first); districts zero-padded (`OH-9` -> `OH-09`); parties via `PARTY_WORDS` and `party_of`,
which also reads trailing tags like `"Chris Pappas (D)"`; titles are stripped and internal
whitespace collapsed first. The year prefix is always `2026`. Anything else returns None.
Acceptance: every title in `supermarket_titles.txt` parses to its `race_key` and `party` column.

`races_for(infos, overrides)` applies `parse_race(info.market_title, info.option)` to every
outcome; a user override (`fair_value_map.json` `overrides[eid]` with `race_key` and `party`)
replaces it with `source="override"`. `races_for` is pure (no I/O) and is used even when fair
value is off (baskets need race groups).

### 4.2 Pins and targets

`fv_pins.PINS` (237 rows, generated from the scout's table; columns in `PIN_COLUMNS`): keyed by
`(race_key, party)` -> Polymarket market id (231 rows), Kalshi ticker (222), `match_kind`
(`NEAR` for chamber control and Independent legs, else `EXACT`). `pins_by_race()` indexes them.
`build_targets(infos, races, overrides)` makes one `MatchTarget` per outcome with
`pins = {"polymarket": id, "kalshi": ticker}` (omit empty ones); an override's `polymarket` /
`kalshi` value replaces the pin, an explicit `null` removes it, `disabled: true` sets
`disabled`. Outcomes without a race get no pins (manual entries can still price them).
**Pins are candidates, not truth**: a provider uses a pinned id only after validating it against
live data (§4.4, §4.5) and drops it otherwise.

### 4.3 Manual fair values (`data/<slug>/fair_values.json` or `.csv`)

The directory is the tracker's data folder (`settings.data_dir / context.label`, demo:
`data/demo`). JSON wins when both files exist.

```json
{"version": 1,
 "values": [
   {"exchange_id": "1070", "probability": 0.55, "source": "Silver Bulletin", "note": "model 57%, shaded", "updated_at": "2026-10-04T12:00:00Z"},
   {"race_key": "2026:SENATE:TX", "party": "D", "probability": "58%", "source": "my model"},
   {"match": "Maine Senate", "party": "D", "probability": 0.52},
   {"match": "re:^Will the Republican Party win the Iowa Senate\\?$", "probability": 0.6}
 ]}
```

CSV: a header row is required; columns (any subset, any order) `exchange_id, race_key, party,
match, probability, source, note, updated_at`; `#` lines are comments.

* `probability`: `parse_probability` (0..1 as is; `"55%"` -> 0.55; numbers in (1, 100] -> /100;
  empty/null = template row, ignored; anything else is an error naming the line).
* `updated_at`: ISO or epoch; missing -> the file's mtime. Older than `MANUAL_MAX_AGE_S` (72 h)
  -> `usable=False`, reason "manual value is older than 72 h; update updated_at".
* Resolution per outcome: `exchange_id` > `race_key`+`party` > `match` (+ optional `party`). A
  `match` that selects more than one outcome (after the party filter) is an error
  ("ambiguous: matches 3 outcomes") and is skipped. Later entries of the same precedence override
  earlier ones (and that is reported as a warning in `errors`).
* Result: `FairValue(source="manual", match_kind="MANUAL", confidence="medium",
  match_confidence=1.0, usable=True, value=p, note, manual_updated_at, as_of=updated_at)`.
* `load()` re-reads only when the mtime changed, never raises, and lists every problem
  (unreadable JSON, unknown keys, bad numbers, unknown exchange ids) in `ManualLoad.errors`.
* `template(targets)` returns a starter document with every outcome and `probability: null`
  (the CLI writes it with `fairvalue --template`, never overwriting an existing file).

### 4.4 Polymarket provider (Gamma, `https://gamma-api.polymarket.com`, no auth)

* **Steady state** (every refresh): `GET /markets?id=<id1>&id=<id2>...&limit=<n>` with at most
  `POLYMARKET_IDS_PER_CALL` (50) ids per call (always pass `limit` = number of ids). About 5
  calls for the 231 pinned ids. The response is a **bare JSON array** of market objects.
* **Validation of a pin** (on its first successful read, then every `DISCOVERY_EVERY_S`): the
  market must have `active == true`, `closed == false`, an `endDate` (or `endDateIso`) in 2026,
  its parent event (`events[0].title`, when present) must not match `REJECT_EVENT_RE`, and its
  `groupItemTitle` must carry the party (`party_of` of a `(D)`/`(R)`/`(I)` tag, or exactly
  `Democrat`, `Republican`, `Democratic Party`, `Republican Party`, `Independent`), equal to the
  target's party. Never validate on the slug (it is wrong for ME-02 and Montana). Failure drops
  the pin with a reason; the outcome then has no Polymarket quote.
* **Discovery** for races without a valid pin, at most every `DISCOVERY_EVERY_S` (6 h):
  `GET /events?tag_slug=midterms&active=true&closed=false&limit=500&offset=k` (pages until a
  short page, at most 3). Accept an event only if its title matches the race
  (`"<State> Senate Election Winner"`, `"<State> Governor Election Winner"`,
  `"<ST>-<NN> House Election Winner"`, or for chamber control the `which-party-will-win-the-senate|house-in-2026`
  slugs), does not match `REJECT_EVENT_RE`, has an `endDate` in 2026, is unique, and has exactly
  one active market whose `groupItemTitle` carries the party. Discovered matches get
  `confidence = CONF_DISCOVERY` (0.85), `source="discovery"`.
* **Parsing** (every variant the scout found): `outcomes`, `outcomePrices`, `clobTokenIds` are
  **JSON-encoded strings** (`json.loads`; tolerate already-decoded lists); `bestBid`, `bestAsk`,
  `lastTradePrice`, `spread`, `volumeNum`, `liquidityNum` are numbers but accept numeric strings;
  `volume` / `liquidity` are strings. YES is index 0 of `outcomes`. Prices: `bid=bestBid`,
  `ask=bestAsk`, `last=lastTradePrice`; if both bid and ask are missing use `outcomePrices[0]` as
  `last` with flag "last-trade-only". Placeholders (`active == false`, or bid 0 / ask 1) are
  dropped with flag "placeholder". There is no quote timestamp: `fetched_at` = our clock,
  `venue_updated_at` = `updatedAt` (informational only).
* **Errors and budget**: one `httpx.Client` per provider, timeout `EXTERNAL_TIMEOUT_S` (8 s),
  `follow_redirects=False`, a `SlidingWindowLimiter(EXTERNAL_READS_PER_MIN=30)` of its own (it
  never touches the Super Market client or its limiter). A connection error, proxy refusal
  (`403` at CONNECT surfaces as `httpx.ProxyError`/`ConnectError`), DNS failure or timeout ->
  status `"offline"`; HTTP 429 -> honour `Retry-After` (else the backoff); 5xx -> `"error"`.
  Consecutive failures back off through `BACKOFF_S` (30, 60, 120, 300, 600 s) via
  `next_try_at`; a refresh during backoff returns status `"backoff"` with no requests. Error
  texts are one sentence, e.g. "Polymarket is unreachable from this machine (connection refused
  by the network proxy): no outside fair value from Polymarket." Never fake a value.
* Do not use `GET /price` (side semantics conflict) or the POST batch endpoints. `/book` and
  `/prices-history` (CLOB) are optional extras, not required.

### 4.5 Kalshi provider (`https://api.elections.kalshi.com/trade-api/v2`, no auth for reads)

* Steady state: `GET /markets?tickers=<t1,t2,...>` (comma-separated, at most 100 per call):
  about 3 calls for the 222 pinned tickers. Response `{"markets": [...], "cursor": "..."}`.
* Validation: `status` in {`active`, `open`} (the response says `active` while the filter says
  `open`), the event ticker ends in `-26`, `-2026` or `-26NOV`, and `rules_primary` names the
  target's party (`Democratic (\(DFL\) )?party` / `Republican party`, case-insensitive). Never
  parse the party from `title` (it is misspelt: "Democratics"). Independents: pinned only by
  ticker; validate by `yes_sub_title` containing a name only when the user provides one
  (otherwise Independent legs are NEAR with confidence 0.8 and need a pin).
* Parsing: prices are 4-decimal **dollar strings** (`yes_bid_dollars`, `yes_ask_dollars`,
  `last_price_dollars`, `no_bid_dollars`, ...), sizes `yes_bid_size_fp` / `yes_ask_size_fp`
  strings. The integer-cent fields were removed on 2026-03-12: ignore `yes_bid`/`yes_ask`/
  `last_price` if present only when the `*_dollars` fields are missing, and then only if they
  look like dollars (<= 1); never treat cents as dollars. `updated_time` -> `venue_updated_at`.
* Events (discovery, optional): `GET /events?status=open&with_nested_markets=true&limit=200&cursor=`;
  with `with_nested_markets=true` the markets are in `event.markets` (top-level `markets` is
  `[]`); handle both.
* Base URL fallback: on a connection error to `KALSHI_BASE_URLS[0]` try `[1]` for that refresh.
  Same timeout, limiter, backoff and error rules as §4.4. `GET /markets/{t}/orderbook` is not
  needed (top of book comes from `/markets`).

### 4.6 Matches and the persisted map (`data/<slug>/fair_value_map.json`)

```json
{"version": 1,
 "updated_at": "2026-10-04T21:00:00Z",
 "overrides": {
   "1070": {"polymarket": "630844", "kalshi": "SENATENH-26-D", "race_key": "2026:SENATE:NH", "party": "D", "disabled": false, "note": "checked by hand"},
   "1057": {"disabled": true, "note": "no outside market for Alaska Governor"}
 },
 "matches": {
   "1070": [{"venue": "polymarket", "external_id": "630844", "label": "Chris Pappas (D) - New Hampshire Senate Election Winner",
             "kind": "EXACT", "confidence": 0.95, "reason": "...", "source": "pin", "validated_at": 1791100000.0}]
 }}
```

* `overrides` are written only by the user; the service never changes them. `matches` are
  written by the service after each successful validation/discovery (atomic: write a temp file
  in the same folder, then `os.replace`); a missing or unreadable file is treated as empty
  (and reported once).
* Confidence: override 1.0; validated pin `CONF_PIN_EXACT` 0.95 (`EXACT`) or `CONF_PIN_NEAR`
  0.80 (`NEAR`); discovery 0.85; a quote whose match confidence is below
  `MIN_MATCH_CONFIDENCE` (0.8) is never used for a fair value.
* `reason` is one plain sentence a human can check, e.g. "Pinned Polymarket market 630844
  (participant map), validated live: active, ends 2026-11-04, 'Chris Pappas (D)' is the
  Democratic leg."

### 4.7 Combining quotes into one fair value

1. Per venue quote: `venue_value(bid, ask, last)` (mid when `0 < bid < ask < 1` and spread <=
   0.10; else last trade with "last-trade-only"; else None) -> `raw_value`.
2. `normalise_race`: per venue and race key, over the legs that venue quoted for that race:
   if every leg has a `raw_value` and the sum is within `RACE_SUM_BAND` (0.95..1.05), set
   `value = raw_value / sum`; otherwise `value = None` with "suspect-sum" for all those legs.
   One quoted leg alone keeps `value = raw_value`. (Kalshi and Polymarket D/R legs sum to ~1.)
3. `blend(eid, quotes, now)`: drop quotes older than `FV_MAX_AGE_S` (300 s, flag "stale") or
   below the match threshold; if none remain -> `FairValue(value=None, usable=False, reason=...)`.
   Otherwise blend in log-odds (clip each value to [0.01, 0.99]) with weights
   `1 / max(spread / 2, 0.005) ** 2` (last-trade-only quotes use spread 0.10). `agreement` =
   max - min of the venue values (None with one). Confidence: `high` if some venue has spread
   <= 0.04 and (one venue, or agreement <= 0.03); `medium` if agreement <= 0.05; else `low` with
   `usable=False` ("Polymarket 0.58 and Kalshi 0.49 disagree by 9 cents: not traded on").
   A NEAR match caps confidence at `medium`. `bid`/`ask` = the tightest venue's. `as_of` = the
   oldest `fetched_at` used. `source` = the venue, or `"blend"`.
4. `combine(manual, external)`: a manual value replaces the external one for that outcome;
   the external quotes stay in `sources`, and `agreement` = |manual - external value|.

Fair values are **not** shrunk here (no favourite-longshot adjustment): that is a strategy
decision (B, `longshot_shrink`).

### 4.8 `FairValueService` (what the tracker owns)

* `FairValueService(directory, mode="auto"|"manual"|"off", providers, manual, recorder, clock)`.
  `mode="off"`: `current().enabled == False`, no files read, no HTTP. `"manual"`: only
  `ManualFairValues`. `"auto"`: manual + `default_providers("auto")`
  (`[PolymarketProvider(), KalshiProvider()]`). The demo passes
  `providers=[demo.DemoFairValueProvider(market)]` instead.
* `set_targets(infos)` after each market-list refresh (open outcomes only); computes races
  (`races_for` with the map's overrides) and targets.
* `refresh(now)`: `manual.load()`; each provider `refresh(targets, now)` (sequentially; each is
  bounded by its own timeouts); normalise, blend, combine; record; keep the snapshot. Never
  raises (an unexpected exception becomes `snapshot.errors` and a log warning).
* **Recording** (for replays): call `recorder(records)` with one `FairValueRecord` per outcome
  whose `(value, bid, ask, usable, confidence)` changed since the last record, plus a heartbeat
  record for unchanged ones every `FV_RECORD_HEARTBEAT_S` (600 s). `detail` = `FairValue.to_dict()`
  without `sources`. The tracker passes `store.add_fair_values`. A recorder exception is caught.
* `current()` is a deep-enough copy (callers may not mutate shared state); `races()`,
  `matches()` (one `MatchRow` per target), `status()` =
  `{"mode", "enabled", "last_refresh_at", "usable", "total", "providers": {name: {"status",
  "last_ok_at", "last_error", "requests", "matched", "quoted", "next_try_at"}}, "manual":
  {"path", "exists", "entries", "errors"}}`.
* Thread-safety: `refresh` runs in the tracker's fair-value worker; `current`/`status`/`matches`
  are called from the paper worker and HTTP threads: guard state with a lock, never hold it
  during HTTP.

## 5. Package B: idea kinds and sizing (`strategy.py`, `sizing.py`)

### 5.1 `generate_signals(inputs, params=None) -> List[Opportunity]`

Every idea of every kind, **unsized** (`suggested_shares = 0`, `suggested_cost = 0`,
`sizing = None`), deterministic (sorted by `score` desc, then `idea_id`). It replaces the
inline idea assembly of `build_report`; `build_report` calls it and then sizes (§5.7).

Common rules for every idea it returns:

* Only open outcomes (`inputs.infos`) with a two-sided quote in `inputs.latest`. The strategy
  does not judge quote age itself: the builders put only *current* quotes in `latest` (the live
  assembler leaves out view rows flagged `stale`; the replay adapter leaves out ticks older than
  `2 x step_s`), so an outcome missing from `latest` simply yields no trade idea.
* Fields always set: `idea_id` (`idea_id_for`), `race_key` (from `inputs.races`), `bet`,
  `exit_plan`, `order_type`, `limit_price`, `max_units` (None when no usable book),
  `settlement_regime = inputs.settlement_regime`, `settles_before_cup_end`
  (`settles_before(..., margin_s=params.settle_margin_s)`), `horizon_hours`, `rationale`,
  `risks`, `confidence`, `score`; plus `fair_value` / `fair_source` whenever a fair value was used.
* `idea_id_for` formats: single `"<kind>:x<eid>:<side>"` (+ `":s<surge_id>"` for fades, +
  `":<extra>"` if needed); sets `"<kind>:set:<eid1>+<eid2>+...:<side1><side2>..."` with legs
  sorted by exchange id (sides as `y`/`n`). The same idea in the next build has the same id.
* `limit_price` (taker): the worst contract price still keeping half the edge:
  `ceil_tick(entry + 0.5 * edge_per_share)`, never above the contract's fair value. Sets: each
  leg `limit = ceil_tick(leg price + 0.5 * set_edge / n_legs)`, and `limit_price` = the sum.
* `max_units`: from the stored book (`inputs.latest[eid].book`, at most `params.book_max_age_s`
  old and consistent with the touch, i.e. the existing `_book_levels`), the units on offer up to
  `limit_price` (sets: `_walk_set`). None when no such book exists.
* `bet` per kind: binary for value/carry (`p = entry + ev`, `gain = 1 - entry`, `loss = entry`,
  `cost = entry`), bracket for fade (`p`, `gain = target_bid - entry`, `loss = entry -
  stop_bid`, `cost = entry`), riskless for basket/arbitrage (`p = 1`, `cost = set cost`,
  `floor = guaranteed payoff`, `gain = floor - cost`, `loss = 0`), fixed for holes
  (`cap_pct = params.hole_max_stake_pct`, `p` = hole_fill_prob, `gain = target_bid - price`,
  `loss = price`, `cost = price`).
* Conflicts (`_resolve_conflicts`, extended): one net position per exchange, so a later idea that
  buys the opposite contract of an earlier (higher-score) idea's leg on the same exchange gets a
  risk line "Conflicts with ..."; a carry opposite an arbitrage/basket leg is dropped as before.
  When an engine-violation `arbitrage` idea buys exactly the legs and sides of a `basket` idea,
  emit only the basket (it carries the exit plan).
* `watch` ideas keep `order_type = "taker"`, `bet = None`, `exit_plan = None` and are never traded.

### 5.2 `value` ideas (`value_opportunity`)

For every open outcome with a fair value `fv` where `fv.usable`, `fv.value is not None`, and
`now - fv.as_of <= params.fv_max_age_s` (manual: `params.manual_fv_max_age_s`):

* Quote: YES bid `b`, ask `a` (both required); `half = (a - b) / 2`.
* For each side: `entry` = `a` (YES) or `1 - b` (NO); `q` = `fv.value` (YES) or `1 - fv.value`
  (NO); if `q < 0.15`, `q = q * (1 - params.longshot_shrink)` (favourite-longshot bias, Page &
  Clemen; say so in the rationale).
* `resolution_gap = q - entry` (EV if held to a 1/0 resolution).
* `target_bid = floor_tick(q - half - params.value_exit_buffer)`;
  `convergence_gain = target_bid - entry` (what selling on convergence banks, exit spread
  included).
* `called = called_prob(race, max(fv.value, 1 - fv.value), params)` (other kinds pass the Cup
  mid's favourite side, `max(mid, 1 - mid)`); `ev, regime_text = regime_ev(
  resolution_gap, convergence_gain, regime, called, params, settles_before_end=...)`:
  * `resolved_outcomes`, or the market settles before the Cup end: `ev = resolution_gap`;
  * `vwap_closeout`: `ev = called * resolution_gap + (1 - called) * unconverged_share * convergence_gain`;
  * `unknown`: `min(resolved ev, vwap ev)` (conservative).
* Keep the side whose `ev` is larger; emit only if `convergence_gain >= min_value_edge` **and**
  `ev >= min_value_edge` (0.02). Otherwise None.
* `prob_win = q`, `edge = ev`, `expected_return = ev / entry`, `target_price = target_bid`,
  `stop_price = None`, confidence = {high: 0.8, medium: 0.6, low: 0.4} for external,
  0.6 for manual/demo, times `fv.match_confidence`; `score = expected_return * confidence`.
* `exit_plan = ExitPlan(kind="value", target_bid=target_bid, dynamic_fv_target=True,
  exit_buffer=params.value_exit_buffer, hold_to_resolution=(regime == "resolved_outcomes"),
  exit_before_ts=<regime rule below>, note="Sell when the YES bid reaches 0.565 (fair value 0.58
  less half the spread and 0.005); otherwise hold")`.
* **Regime exit rule** (all kinds): `exit_before_ts = cup_end - params.closeout_buffer_s` when
  the regime is `vwap_closeout`, or when it is `unknown` and the race's state is in
  `SLOW_COUNT_STATES`; else None. Markets settling before the Cup end never get one.
* `called_prob(race, fav, params)`: `fav >= 0.95` -> `called_prob_safe` (0.97; 0.80 if the state
  is in `RCV_STATES`); state in `SLOW_COUNT_STATES` -> `called_prob_slow` (0.40); known race
  elsewhere -> `called_prob_fast` (0.85); no race -> the mean of fast and slow.
* Rationale (examples of the required content, wording free): fair value with source,
  confidence and age; the gap at the ask; the exit target and what it banks; the regime
  sentence from `regime_ev`; depth at the limit when known. Risks: outside prices can be wrong
  (biases, fees, different resolution rules: Polymarket media calls/certification, Kalshi
  swearing-in); faster bots close gaps first; under a VWAP closeout an unclosed gap pays ~0.

### 5.3 `basket` ideas (`group_races`, `basket_opportunities`)

**Groups** (`group_races(infos, races, constraints)`):

* *Race groups*: open outcomes sharing a `race_key` with **different parties**, at least two
  (the Cup's D/R pairs, D/R/I triples). Not exhaustive (an unlisted winner makes every leg NO).
* *Market groups*: all open outcomes of one multi-outcome market (`MarketInfo.is_multi`, i.e.
  `ExchangeInfo`s sharing a `market_id`), at least two. Exhaustive only if an option matches
  `CATCH_ALL_RE` ("Any other candidate") or an engine relationship of type `complementary`
  covers every member (`constraints["data"][i]["relationshipType"]`/`"type"`, members via
  `_members`). `why_exhaustive` says which.
* Deduplicate by member set (a market group whose members are also a race group is one group,
  source "market").

**NO basket** (any group): every leg needs a YES bid `b_i`. `S_b = sum(b_i)`. If `S_b - 1 >=
basket_min_edge` (0.01): buy NO on every leg at `1 - b_i`; set cost `C = n - S_b`; guaranteed
payoff `floor = n - 1` (exactly `n - 1` if exhaustive, at least `n - 1` otherwise); `edge =
floor - C = S_b - 1` per set.

**YES basket** (exhaustive groups only): every leg needs a YES ask `a_i`; `S_a = sum(a_i)`; if
`1 - S_a >= basket_min_edge`: buy YES on every leg; `C = S_a`, `floor = 1`, `edge = 1 - S_a`.
For non-exhaustive groups never emit it (add nothing: it is not riskless).

**Depth**: `max_units = _walk_set(leg levels, limit_price)` with the §5.1 set limit (each leg
`ceil_tick(price + 0.5 * edge / n)`, so a further set keeps at least half the edge), from stored
books; None if any leg lacks a usable book (the paper engine then fills only what the fresh
books show, up to each leg's `limit`).

**Exit plan**: `ExitPlan(kind="basket", min_set_profit=max(basket_exit_min_profit,
basket_exit_fraction * edge), hold_to_resolution=(regime == "resolved_outcomes"),
exit_before_ts=<regime rule>, note="Sell the set when selling every leg brings at least
+0.025 per set over its cost (for a NO basket: entry bid sum minus exit ask sum); otherwise
hold to settlement")`. For a NO basket the exit proceeds per set are `sum(1 - a_i_now)`, so
`profit = S_b(entry) - S_a(now)`.

**Reporting**: `unit="sets"`, `legs` (shape in §3), `entry_price = C`, `edge`, `expected_return
= edge / C`, `prob_win = 1.0`, `confidence` 0.9 (race group) / 0.95 (exhaustive market group),
`profit_per_capital_day = edge / (C * max(1/24, days_until_settlement))` with
`days_until_settlement` from the latest leg settlement date (Cup markets: the Cup end), `score =
expected_return * confidence`. Rationale: the bid (or ask) sum, the per-set profit in SUSQies,
the per-day return on capital, the exit rule, and for NO baskets "pays even if a third
candidate wins (then n NO shares pay)". Risks: legging (one leg fills, the other moves), capital
locked until the exit or settlement, under a VWAP closeout each leg is cashed separately (not
locked), a tournament ruling/REFUND on one leg.

### 5.4 `hole` ideas (`hole_candidates`, `hole_opportunities`)

Passive resting buy orders far below a liquid favourite, to catch a careless market order that
sweeps a thin book ("liquidity hole"). Legitimate liquidity provision; never a spoof (each order
is meant to fill, and is small).

* Eligible outcome: two-sided quote with `ask - bid <= hole_max_spread` (0.02); favourite side
  mid >= `hole_min_mid` (0.70) (YES mid >= 0.70 -> buy YES; YES mid <= 0.30 -> buy NO); no
  open surge of any verdict on it; a stored book at most `book_max_age_s` old whose favourite-
  side best bid quantity (YES bids for YES; YES asks for NO) is >= `hole_min_touch_qty` (200).
  `hole_candidates` returns the outcomes that pass everything except the book (no recent book),
  at most `2 * hole_max_exchanges`, tightest spread first then exchange id: the runner reads
  their books.
* `ref` = the contract's fair value if a usable `fv` exists, else the contract mid.
  `price = floor_tick(ref * (1 - hole_depth_fraction))`, required `<= contract best bid -
  hole_min_ticks_below * 0.005` and `>= 0.05`.
* At most `hole_max_exchanges` (4) hole ideas, ranked by touch quantity x (1 / spread).
* `order_type="maker"`, `limit_price=price`, `expires_at = now + hole_ttl_s` (6 h), `max_units =
  hole_max_shares` (500). `exit_plan = ExitPlan(kind="hole", target_bid=floor_tick(max(price +
  0.05, ref - hole_exit_buffer)), time_stop_after_fill_s=hole_time_stop_s, exit_before_ts=<regime
  rule>, note="If it fills, sell when the bid recovers to 0.900, or after 12 h")`.
* `edge = hole_fill_prob * (target_bid - price)` (expected, tiny), `prob_win = hole_fill_prob`,
  `confidence = 0.5`, `score = edge / price * confidence`. Rationale explains the hole and that
  most such orders never fill; risks: adverse selection (it fills exactly when real news hits),
  the house can sweep its quotes, cancel before scheduled news (the order is cancelled
  automatically when a surge opens on the outcome, since the idea then disappears).

### 5.5 Changes to fade, carry and arbitrage (the wrong assumptions, fixed)

Numbers refer to `paper/codebase_map.md` §5.

1. **Settlement dates** (#9): `settles_before` replaces `_settles_before` for decisions: a
   settlement date equal to the Cup end (every real Cup market) is the closeout, not a
   resolution: "settles before" only if at least `settle_margin_s` (1 h) earlier. Risk text:
   "a settlement date is not a payout date: autosettlement can retry, REFUND and tournament
   rulings exist".
2. **Post-Cup valuation** (#1): remove the `score x 0.5` rule. Carry edges use `regime_ev` with
   `resolution_gap = p_true - entry` and `convergence_gain = 0` (a stable favourite does not
   converge further), so under `unknown`/`vwap_closeout` a carry that settles at the Cup end
   earns `called x gap`. Rationale states the regime and the called probability. Carry gets
   `exit_plan = ExitPlan(kind="settle", hold_to_resolution=True, exit_before_ts=<regime rule>,
   note="Hold to settlement (pays 1.00 if it wins)")`.
3. **Carry fair value** (#11): `p_true = fv contract value` when a usable fair value exists (and
   say so), else the old rule of thumb, labelled "rule of thumb, not a measured edge".
4. **Fade exit spread** (#10): `target_bid = target - half_spread`, `stop_bid = stop -
   half_spread` (contract terms); `gain = target_bid - entry`, `loss = entry - stop_bid`. With a
   usable fair value: if the fair value lies at or beyond the half-reversion target (the spike
   moved away from fair value) use `p = max(p, 0.65)` and say so; if it lies beyond the peak in
   the move's direction (the move went toward fair value) drop the fade. `exit_plan =
   ExitPlan(kind="bracket", target_bid, stop_bid, time_stop_ts = now + fade_horizon_h * 3600)`.
5. **Arbitrage held past the Cup** (#2) and **sizing** (#4): arbitrage sets get a basket-style
   `exit_plan` and a riskless `bet`; sizes come from the policies (riskless caps, §5.6), and
   `all_collateral` (when configured) is honoured by the policies.
6. **NO basket** (#3): the new `basket` kind (§5.3); arbitrage keeps the engine-violation path.
7. **Backtest reversion rate** (#12): `backtest_fade` measures the fade return **net of the
   spread**: enter at the detection-time ask (YES) / `1 - bid` (NO) and exit at the horizon's
   bid, from tick bid/ask; candle-only points use an assumed spread of 0.02 (and a note says
   so). Add `net_of_spread: bool = True` (False restores the old mark-to-mark numbers) and keep
   the result fields.
8. **Principles text** (#6, #7): replace "variance is your friend: take more, bigger,
   independent bets" with the chaser rule ("when behind, concentrate on your best edges and
   accept correlated exposure; diversifying across independent longshots destroys the chance of
   a large multiple"), and replace the diversification line with "races share one national
   polling error: a same-party slate of toss-ups is one bet; diversify only to protect a lead".
   Replace the settlement-date principle with the regime-aware one ("the Cup's end rule is
   unknown: prefer positions that pay under both a real resolution and a 5-hour VWAP closeout").
9. **Risk mode** (#5) stays as a label and score multiplier for backward compatibility, but the
   report now also carries the policy explanation (§5.7) and sizes come from the policy.

### 5.6 Sizing policies (`sizing.py`)

#### 5.6.1 Common mechanics

`kelly_units(p, gain, loss, W, k) = k * W * (p / loss - (1 - p) / gain)` (0 if <= 0). For a
binary bought at `c` this equals the legacy `size_position`; for a bracket it equals
`_bracket_shares` (proof: `f = (p - c)/(1 - c)` with `c = loss/(gain + loss)`). Keep the legacy
`+1e-9` before every `floor`.

For one idea (`size`), with `W = ctx.equity`:

| bet kind | uncapped units | caps |
|---|---|---|
| binary / bracket | `kelly_units(p, gain, loss, W, kelly_mult)` | `idea_cap * W / cost`; race cap; tilt cap; total cap; cash; depth |
| riskless | `riskless_cap * W / cost` | total cap; cash (`cost` per unit, or `max(0, cost - floor)` with `all_collateral`, then notional `<= ALL_COLLATERAL_NOTIONAL_PCT * W / cost`); depth |
| fixed | `min(max_units or inf, cap_pct * W / cost)` | race cap; total cap; cash |

* Race cap: `(exposure.by_race[race] + new cost) <= race_cap * W`; tilt cap: the new position's
  signed Democratic tilt (`+cost` for YES-D or NO-R, `-cost` for YES-R or NO-D, 0 for I/O or no
  race) may not push `|national_tilt_d|` above `tilt_cap * W` (positions that reduce |tilt| are
  never capped by it); total: `exposure.gross_cost + new cost <= total_cap * W`; cash: `units *
  cash_per_unit <= ctx.free_cash` (never more than the available cash); depth: `units <=
  opp.max_units` when known. Race and tilt caps do not apply to riskless kinds.
* `units = floor(min(...) + 1e-9)`; < 1 -> 0 with reason. `stake = units * cash_per_unit`.
* `capped_by` lists the binding cap(s) by name; `lines` explains every number, e.g.
  "Quarter-Kelly on YES at 0.52 with a fair value of 0.58 (edge +0.047): 3.4% of equity, 3,423
  SUSQies", "Capped at 8% of equity per idea", "Capped by the free cash (1,200 SUSQies left after
  pending orders)", "The book offers 1,850 shares up to 0.545".
* `size_all(opps, ctx)`: sort by `score` desc then `idea_id`; size each in turn against
  exposure and free cash updated by the earlier decisions; return `{idea_id: SizeDecision}`.
  `size(opp, ctx)` sizes one idea against the given exposure only (what the Strategy view
  shows: every card is sized as if it were the only new idea).

#### 5.6.2 `ConservativePolicy` (`name="conservative"`)

`kelly_mult 0.25`, `idea_cap 0.08`, `riskless_cap 0.08`, `total_cap 0.60`, `race_cap 0.12`,
`tilt_cap 0.30`. With an empty exposure and `equity = cash` it must reproduce the legacy sizes of
`fade_opportunity`, `carry_opportunity` and `arbitrage_opportunities` exactly (existing tests).
`explain(ctx)` = `{"policy": "conservative", "label", "mode": None, "lines": ["Quarter-Kelly,
at most 8% of equity per idea, 12% per race, 60% in total", "Same-party exposure across races is
capped at 30% of equity: races share one national polling error"], "bar", "M", "markov_ceiling",
"ev_multiple"}` (bar fields filled when `ctx.bar` is known, for information).

#### 5.6.3 Bar estimate and Markov ceiling

`estimate_bar(leaderboard, history, initial, days_left)`:

* `value(entry) = entry["value"]` or `initial + entry["pnl"]`. `third`, `tenth`, `hundredth` =
  the 3rd/10th/100th highest values (None if missing).
* Growth: the oldest history snapshot at least 12 h older than `leaderboard.at` with a third
  value: `g = (third_now / third_then) ** (1 / days_between) - 1`, clipped to [0, 0.05].
* `projected = third * (1 + g) ** days_left`, capped at `BAR_CAP_MULT (10) * initial`.
* `value = max(projected if growth known else third, BAR_FLOOR_MULT (2) * initial)`; `method` =
  "projected" | "third" | "floor" (floor when third is unknown or below the floor).
* `explanation` always includes: "Leaderboard values are mid-Cup marks (cash plus positions at
  current prices), not settled balances; thin-market marks can be inflated." and how the value
  was formed.

`markov_ceiling(ev_multiple, M) = min(1, ev_multiple / M)` where `ev_multiple = 1 +
ctx.expected_profit / ctx.equity`: no strategy reaches `M` times its value with a probability
higher than this.

#### 5.6.4 `ChaserPolicy` (`name="chaser"`)

`M = bar.value / ctx.equity` (None without a bar). Mode:

| mode | when | rules |
|---|---|---|
| `unknown_bar` | no bar | half-Kelly, idea 15%, race 25%, total 80%, no tilt cap |
| `near` | `M <= 1.3` | half-Kelly, idea 12%, race 25%, total 70%, no tilt cap |
| `chase` | `1.3 < M <= 10` and `days_left > SWING_DAYS (2)` | full Kelly, idea 25%, race 35%, total 95%, no tilt cap; **concentrate**: only the `top_k = 5` best directional ideas (binary/bracket bets, by score) get capital in `size_all` (others: 0, `capped_by=["top_k"]`) |
| `swing` | `1.3 < M <= 10` and `days_left <= 2` | as `chase`, plus **bold-to-goal** for directional ideas with `settles_before_cup_end` True or `called_prob >= 0.85`: `stake = min((bar - W) * c / (1 - c), SWING_BOLD_CAP_PCT (60%) * W, free cash)` (the stake whose win state reaches the bar), units = stake / c |
| `out_of_reach` | `M > 10` | exactly the conservative rules; line "The bar is more than 10x your value: the prize is out of reach in expectation, so size for a steady record (Smart Score) instead" |

Riskless kinds use `CHASER_RISKLESS_CAP_PCT` (50%); fixed kinds the conservative rule. Hard caps
and "never more than the free cash" apply in every mode. `explain(ctx)` lines must cover: the
bar and how it was estimated, `M`, the Markov ceiling ("Even a perfect strategy reaches 2.2x your
value with probability at most 47%, given an expected multiple of 1.04x"), the mode and its rules,
"Correlated, same-party exposure is allowed: a chaser needs one large favourable outcome, and
independent bets average it away", and "Sizes never exceed the free cash".

`get_policy("conservative" | "chaser")` returns a fresh object; anything else raises ValueError.

### 5.7 `build_report` and `report_from_inputs`

settlement_regime="unknown", leaderboard=None, bar=None, sizing="conservative", params=None,

existing tests hold; the new kinds append the decision's first line), applies the risk-mode

Report fields: `sizing_policy`, `sizing = {**policy.explain(ctx), "alternative": other.explain(ctx)}`,

## 6. Package C: the paper engine (`paper.py`) and the backtest (`backtest.py`)

### 6.1 Portfolios and capital

`PaperConfig.portfolios` defaults to `default_portfolios()`: `policy:conservative`,
`policy:chaser` (every trade kind), and one conservative portfolio per kind (`kind:value`,
`kind:basket`, `kind:hole`, `kind:fade`, `kind:carry`, `kind:arbitrage`). Every portfolio starts
with the same capital (equal capital, so the per-kind rows compare edges). Start capital, in
order: `PaperConfig.start_capital` / the reset request's value ("set by you"); the real account
value ("account value"); the real cash ("cash"); the tournament's initial balance ("initial
balance"); 100,000 ("default 100,000"). The runner passes the value and its source to
`engine.start`. Portfolios are independent what-ifs: they share signals and reads but not
liquidity, cash or positions.

### 6.2 One step (`run_step` and `PaperEngine.step`)

`run_step(engine, inputs, obs, fulfil, signal_fn, candidates_fn, decided_at)`:

1. `plan = engine.wanted_reads(obs.now, obs, candidates_fn(inputs))`.
2. `books, tape, skipped = fulfil(plan, obs.now)`; merge (`obs.books[eid]` replaced by a newer
   observation; `obs.trades[eid]` extended, sorted by ts, deduplicated by trade id).
3. `signals = signal_fn(inputs, inputs.params)`.
4. `report = engine.step(now, obs, signals, inputs)` with `now = decided_at()` (live: the clock
   after the reads) else `obs.now`; the read counts and `skipped` go into the report.

`PaperEngine.step(now, obs, signals, inputs)` runs these phases **for each portfolio, in config
order**, then persists:

1. **Taker fills** for orders with status `pending` (§6.3). Orders whose `created_at +
   max_fill_delay_s < now` and are still unfilled expire ("No order book read within 120 s of
   the decision: not filled").
2. **Maker fills** for `resting` and `cancelling` orders from `obs.trades` (§6.4). A resting
   order whose idea was absent from `signals` for `maker_cancel_after_missing_steps` (2)
   consecutive steps, or whose `expires_at` passed, becomes `cancelling` with `cancel_at` = that
   step's time (or `expires_at`): the real order would have rested until then, so prints up to
   `cancel_at` still fill it. It closes (`cancelled` / `expired`, "The conditions for this
   resting order no longer hold" / "Expired unfilled") at the first step whose tape for that
   exchange was read after `cancel_at`, or `max_fill_delay_s` after `cancel_at` without such a
   read (no further fills). Settlement or closure of the outcome cancels at once.
3. **Settlements and closures** (§6.6).
4. **Marks** of every open position (§6.7).
5. **Exits** (§6.5): create exit orders (taker, `purpose="exit"`), filled from the next step on.
6. **Entries**: eligible signals = kind in `TRADE_KINDS` and in the portfolio's `kinds`; quote
   not stale; outcome open; `now < cup_end`; no open position, pending/resting order or
   cooldown (`reentry_cooldown_s` after an idea closes) for the same `idea_id`; no open position
   or order on any exchange the idea touches (one net position per exchange); the portfolio
   below `max_open_positions`. Size them with `policy.size_all(eligible, ctx)` (§6.8 builds
   `ctx`); create at most `max_new_orders_per_step` orders (best score first): taker ideas ->
   `pending` buy order(s) at `limit_price` (sets: one order per leg, shared `group_id`, each at
   the leg's `limit`, qty = units); maker ideas -> `resting` buy order at `limit_price`,
   `expires_at`, `queue_ahead` = the displayed quantity at exactly that YES price on that side
   of the newest book (None if no book). Reserve cash (§6.8). `reason` = the idea's first
   rationale line.
7. **Equity points** for every portfolio (§6.7), drawdown update.
8. **Persistence** (§6.11); the final snapshot when `hours_run` first reaches `target_hours`.

Orders created at a step are never filled in that same step (they need an observation made
after `created_at + min_latency_s`, and every observation in this step predates the decision).

### 6.3 Taker fill model (no look-ahead, real depth, no liquidity re-use)

For a pending order on exchange `e` created at `t0`:

* The fill observation is **the first** `BookObservation` for `e` with `t0 + min_latency_s <=
  observed_at <= t0 + max_fill_delay_s` (the engine remembers, per order, which observation it
  used; a later, better book is never chosen instead). In the live loop that is the book read
  at the next step; in the backtest the adapter supplies it (§6.12).
* No fill while the outcome's bulk quote is older than `stale_quote_s` (the order waits, then
  expires).
* Levels: `contract_levels(book, side, action)`, minus liquidity this portfolio already took on
  that exchange side within `consumed_memory_s` (900 s): for every earlier fill level at the same
  YES price on the same side, subtract its quantity from the newer book's level at that exact
  price (never below 0), whatever the newer book shows (we never traded, so a real refill cannot
  be ours to take twice). Older consumption is forgotten.
* `walk(levels, remaining, limit, buy)`: best first, only prices no worse than the limit, whole
  shares. One `PaperFill` per order per step (`levels` = what was walked, `price` = average,
  `book_at`, `latency_s`). **Entry** orders are immediate-or-cancel: the unfilled remainder is
  cancelled, `close_reason="The book had only 1,200 of 2,000 shares at 0.545 or better"`.
* Sets: legs fill independently against their own books. After every leg has an outcome
  (filled, partly filled, cancelled or expired), `sets = min(filled qty over legs)`; any leg's
  excess over `sets` is **legging residue**: an exit order for it is created at once (purpose
  "exit", reason "Legging: the other legs filled only 300 sets", limit = 0.005, i.e. sell into
  whatever the next book shows), closed as a trade with `exit_reason="legging"`.
* **Exit** (sell) orders walk the bids of the contract (`contract_levels(..., "sell")`) down to
  their limit; shares the book cannot absorb stay pending and fill from the next observation made
  after the one already used (never the same observation twice), until `max_fill_delay_s` after
  their own `created_at`; then they expire and the next exit evaluation creates a new one.

### 6.4 Maker fill model (trade-through, queue haircut)

A resting buy of contract `side` at contract price `L` rests at YES price `P = L` (YES) or
`P = 1 - L` (NO, a YES ask). For each tape print `(id, ts, price q, size z)` in `obs.trades[e]`
with `ts > created_at + min_latency_s`, `ts <= now`, `ts <= cancel_at` (when cancelling), not in
`seen_trade_ids`:

* **Through**: YES side: `q < P - 1e-9`; NO side: `q > P + 1e-9`. Fill `min(remaining, z)` at `L`.
* **At the price** (`|q - P| <= 1e-9`): if `queue_ahead` is None, no fill; else the print first
  consumes `queue_ahead`; of what is left, `queue_haircut x left` (0.5) fills, at most `remaining`.
* Never better than `L`, never more than the printed size, never from prints before placement.
* `last_trade_ts` / `seen_trade_ids` (newest 500) advance; one `PaperFill` per order per step
  (`liquidity="maker"`, `trade_ids`, `book_at` = the newest print used).
* A tape read that failed or was skipped produces no fills (the order keeps waiting).

### 6.5 Exits

For each open position, in this order, the first rule that fires creates an exit order for the
whole quantity (baskets: one order per leg, shared `group_id`). Bids are the contract's touch
bid from the bulk quote (YES bid, or `1 - YES ask` for NO); a stale quote fires nothing except
the regime and time rules.

1. Settlement (phase 3, not an order).
2. `exit_before_ts` reached -> reason "regime", limit 0.005.
3. `stop_bid` and bid <= stop -> "stop", limit 0.005.
4. Target: `target_bid` and bid >= target -> "target", limit = `target_bid - 0.005`; value
   positions with `dynamic_fv_target` and a usable current fair value use `target =
   floor_tick(fv_contract - half_spread - exit_buffer)` instead (reason "fair_value" when the
   fair value moved, "converged" otherwise). Baskets: per-set proceeds `sum(contract bids of the
   legs) - set cost >= min_set_profit` -> "converged", each leg limit = its bid - 0.005.
5. `time_stop_ts` reached, or `time_stop_after_fill_s` after `first_fill_at` -> "time", limit 0.005.
6. `hold_to_resolution` or none fired: keep.

A position with a pending exit order gets no second one. The trade's `exit_reason` is the reason
of the exit order that closed it.

### 6.6 Settlement, closure without a ruling, Cup end

* An outcome in `obs.settlements` with `payout_yes` 1/0: every open position on it is paid
  `qty x payout` (YES) or `qty x (1 - payout)` (NO) as a `PaperFill(action="settle",
  liquidity="settlement", purpose="settlement", price=payout per share)`; open orders on it are
  cancelled; the position closes (trade `exit_reason="settled"`). `refund=True`: proceeds = the
  position's cost (`exit_reason="refund"`). `payout_yes is None` and not refund: treat as below.
* An outcome not in `obs.open_ids`, not settled: positions become `frozen` with flag
  `closed_no_ruling`, valued at their last liquidation value, no orders, no exits; they unfreeze
  if the outcome reappears.
* At and after `cup_end`: no entries and no exits; positions keep their last liquidation value,
  flag `post_cup`, until settled.

### 6.7 Valuation

Per open position, every step:

* `liq_value, depth_known = liquidation_value(side, qty, book, quote)` with `book` = the newest
  observation for the exchange at most `mark_book_max_age_s` old **and** consistent with the
  quote (its best level within one tick of the touch; else ignore it). Shares beyond the book's
  depth are worth 0. No book: `qty x touch bid` with flag `depth_unknown`. No bid: 0.
* `mark_value` = `mid_value(side, qty, quote)` (reference). `fv_value` = `qty x fv_contract` when
  a usable fair value exists (model reference, never the headline).
* Portfolio: `positions_liq = sum(liq_value)`, `equity_liq = cash + positions_liq -
  outstanding collateral advances`; likewise `equity_mark`, `equity_fv` (positions without a fair
  value count at liquidation value; None when no position has one). `pnl_liq = equity_liq -
  start_capital`; `unrealized_pnl_liq = positions_liq - cost of open positions`.
* Drawdown: running peak of `equity_liq`; `max_drawdown_abs = max(peak - equity_liq)`,
  `max_drawdown = max((peak - equity_liq) / peak)`.

### 6.8 Accounting

* `cash` includes `reserved_cash`; `free_cash = cash - reserved_cash`.
* Entry buy orders reserve `qty x limit_price` at creation (sets: per leg); never create an order
  whose reservation exceeds `free_cash` (the policy already sized within it). On a fill: `cash
  -= qty x price`, the reservation shrinks by `qty x limit_price`; on close the rest is released.
* `all_collateral` (riskless sets only): the entry reservation is `units x max(0, limit_price -
  floor)` split evenly across the legs (the policy sized on that cash need); when the legs of a
  set fill, the full cost is debited and `advance = min(set cost, floor) x sets` is credited back
  at once and recorded on the legs' `collateral_advance` (split evenly); it is repaid (subtracted
  from proceeds) when the set is sold or settles. Equity subtracts outstanding advances.
* Sells add `qty x price` to cash; settlement adds the payout. A partial exit moves
  `qty x (price - avg_cost)` into the position's `realized_pnl`; `avg_cost` is unchanged.
* A position closes when its qty reaches 0; one `PaperTrade` per closed position, or per basket
  when its last leg closes (`legs` lists each leg; `qty` = sets; `cost`, `proceeds`, `pnl`,
  `return_pct = pnl / cost`, `hold_hours`, `profit_per_capital_day = pnl / (cost x max(hold days,
  1/24))`). The idea enters cooldown.
* `SizingContext` for a portfolio: `equity = equity_liq`, `cash`, `free_cash`, `start_capital`,
  `cup_end`, `days_left = max(0, (cup_end - now) / 86400)`, `exposure` (gross = cost of open
  positions + reserved cash; by race (race key, else `market:<id>`); by idea; national tilt per
  §5.6.1; open count), `bar = inputs.bar`, `expected_profit = sum(qty x edge_per_unit)`,
  `my_rank = inputs.my_rank`, `regime = config.regime`, `all_collateral`, `races = obs.races`.
* Ids (deterministic, per run): `run_id = "run-<int(started_at)>"` (suffix `-2`, `-3` on
  collision); `order_id = "<pid>:o<n>"`, `fill_id = "<pid>:f<n>"`, `trade_id = "<pid>:t<n>"`,
  `basket_id = "<pid>:b<n>"`, `position_id = "<pid>:<eid>"`.

### 6.9 Verdict (`compute_verdict`)

Inputs: closed trades of the portfolio, `pnl_liq`, `hours_run`, `max_drawdown`.

* `n` closed trades; clusters = distinct `race_key` (else `market:<first exchange's market>`);
  `mean`, `ci = bootstrap_ci(pnls, clusters)` (cluster bootstrap, 2,000 resamples, seed 12345,
  90% percentile interval; None with < 2 clusters); wins (pnl > 0) and `wilson_interval` (z
  1.645); best trade; `pnl_ex_best = pnl_liq - max(0, best)`.
* Level:
  * `insufficient` if `hours_run < 12` or `n < 20` or `clusters < 8`;
  * else `positive` if `ci_low > 0` and `pnl_ex_best > 0` and `pnl_liq > 0`;
  * else `negative` if `ci_high < 0` and `pnl_liq < 0`;
  * else `inconclusive`.
* Sentences (exact templates; `{pnl}` = `f"{x:+,.0f}"`, `{lo}`/`{hi}` = `f"{x:+,.1f}"`,
  `{h}` = `f"{x:.1f}"`, plural `s` on trade/race):
  * insufficient: `Not enough evidence yet: {n} closed trade{s} across {k} race{s} in {h} h. A verdict needs at least 20 closed trades across 8 races and 12 hours; P&L so far {pnl} SUSQies at liquidation value.`
  * positive: `Profitable so far: {pnl} SUSQies at liquidation value over {h} h and {n} closed trades; the 90% interval for the average trade is {lo} to {hi} SUSQies, and the result stays positive without the best trade ({ex}).`
  * negative: `Losing so far: {pnl} SUSQies at liquidation value over {h} h and {n} closed trades; the 90% interval for the average trade is {lo} to {hi} SUSQies, entirely below zero.`
  * inconclusive: `Inconclusive: {pnl} SUSQies at liquidation value over {h} h and {n} closed trades, but the 90% interval for the average trade ({lo} to {hi} SUSQies) includes zero.` + ` Without the best trade the result is {ex}.` when `pnl_ex_best <= 0 < pnl_liq`.
* `reasons`: one line per unmet threshold ("only 7 closed trades (needs 20)") or per condition
  that set the level. `caveats` = `CAVEATS` (+ `DEMO_CAVEAT` in demo). `thresholds =
  {"min_hours": 12, "min_trades": 20, "min_clusters": 8}`.

### 6.10 Read plan and budget (the runner)

`engine.wanted_reads(now, obs, candidates)` returns requests in priority order, one per
`(kind, exchange)`:

1. Books for exchanges with pending taker orders (entries, exits, all legs) that have no
   observation yet satisfying their fill window; `after = created_at + min_latency_s`.
2. Tape for exchanges with resting orders, if not read in the last `trade_poll_s` (60 s), oldest
   poll first, and for exchanges with `cancelling` orders not read since their `cancel_at`
   (regardless of `trade_poll_s`, first); `since` = the oldest `last_trade_ts`/`created_at` of
   their orders.
3. Books for open positions whose newest observation is older than `mark_refresh_s` (300 s),
   oldest first.
4. Books for `candidates` (hole candidates) and for the top 3 ideas the previous step sized > 0
   whose `max_units` was None, if their newest book is older than `2 x 30 s`.

`PaperRunner` fulfils requests in order while `limiter.used < limiter.limit`, at most
`max_book_reads_per_step` (8) books and `max_trade_reads_per_step` (2) tapes; the rest are
`skipped` (counted in `StepReport.reads_skipped` and `budget.reads_skipped_last_step`). A reader
returning None is a failed read (no data, no retry this step). The runner never calls anything
on the reader except `book` and `trades`.

**Budget arithmetic** (live, 30-s steps): at most 8 + 2 = 10 reads per step = 20/min, and the
paper limiter is 20/min, so the paper worker uses **at most 20 of the 90 reads/min** the client
allows. See §9 for the whole account.

### 6.11 Persistence, restart, reset

* After every step: `paper_save_run(run_id, started_at, config, state, now)`; changed orders via
  `paper_put_orders`; new fills, trades and equity points via the `paper_add_*` methods.
* `state()` JSON: `{"version": 1, "run_id", "started_at", "start_capital", "capital_source",
  "target_hours", "steps", "last_step_at", "last_step_seconds", "counters": {pid: {"o", "f", "t",
  "b"}}, "portfolios": {pid: {"cash", "reserved_cash", "peak_equity", "max_drawdown",
  "max_drawdown_abs", "realized_pnl", "fills", "positions": [PaperPosition], "orders":
  [open PaperOrder], "consumed": [[exchange_id, book_side, yes_price, qty, at]], "cooldowns":
  {idea_id: until}, "missing": {order_id: steps}, "fill_obs": {order_id: observed_at}}},
  "final": null | {"at", "verdicts": {pid: Verdict}, "portfolios": [PortfolioSummary]},
  "last_signals": {"count", "by_kind", "at", "top_bookless": [idea_id]}}`.
* Construction: `paper_load_run(None)` = the newest run without `ended_at`; continue it (its
  config's portfolio ids must match the current config, else end it and start fresh). A gap in
  time is fine (the equity curve shows it).
* `reset(now, start_capital, capital_source, target_hours)`: mark every open position as closed
  at its liquidation value (trades with `exit_reason="reset"`, kept in the old run's history),
  `paper_end_run`, then `start` a new run.
* `MemoryPaperPersistence` implements the protocol in memory (tests, backtests); TrackerStore
  implements it in SQL (E). Both must pass the same contract test (§7.8).

### 6.12 Backtest (`backtest.py`)

#### 6.12.1 Flow

`run_backtest(source, config, signal_fn=None)`:

1. `market = HistoricalMarket(GuardedHistory(source), config)`; window `[start, end]` (config,
   else `end` = newest tick, `start = end - hours`); decision times `start, start + step_s, ...,
   <= end`.
2. Engine: `PaperEngine(config.paper with regime/params overrides applied, persistence=
   MemoryPaperPersistence())`; `paper.min_latency_s = config.latency_s`;
   `paper.max_fill_delay_s = max(paper.max_fill_delay_s, config.step_s + config.latency_s)`.
   Start capital = `config.paper.start_capital` or 100,000.
3. For each `t`: `guard.set_time(t)`; `inputs = market.inputs(t)`; `obs = market.observation(t)`;
   `run_step(engine, inputs, obs, fulfil=market.fulfil, signal_fn)`, where `market.fulfil(plan, t)`
   returns, for each book request, the first observation with `observed_at >= after` (or the
   newest `<= t` for marks), never later than `t`, and for each tape request the stored prints in
   `(since, t]` (or candle fills, below). The same per-step read caps apply (no per-minute
   limiter).
4. Report: portfolios, equity curves, trades, verdicts (hours = window hours), coverage,
   assumptions, warnings.

#### 6.12.2 What the adapter may use at decision time `t`

* Quotes: the newest tick with `ts <= t` no older than `2 x step_s`; else, if the newest
  candle closed at or before `t` (bucket start + length `<= t`) is no older than 1 h, a synthetic
  quote `bid = floor_tick(close - assumed_spread / 2)`, `ask = ceil_tick(close + assumed_spread
  / 2)`; else no quote.
* Books: stored `book_snapshots` with `ts <= t` (for decisions: at most 900 s old), when
  `use_book_snapshots` and one exists; otherwise a **synthetic book**: one level at the quote's bid and one at
  its ask, each `min(assumed_touch_qty, volume_share x volume of the last closed 1h candle)`
  (at least 1 share when a candle exists, else `assumed_touch_qty`), `source="synthetic"`. Fill
  observations for pending orders: the first snapshot (or the first tick, made into a synthetic
  book) with `ts >= after` and `<= t`.
* Tape for maker fills: stored trades in `(since, t]`; if the exchange has no stored trades in
  the window, candle trade-throughs: a closed 5m (else 1h) candle with bucket start `>= since`,
  close `<= t`, and `low < P` (YES bid) / `high > P` (YES ask) fills `min(remaining, volume_share
  x volume)` at the limit (flag "candle fill" in the fill reason).
* Surges: re-detected from `series(eid, t - SURGE_LOOKBACK_S, t)` with `analytics._SurgeScanner`
  semantics (no look-ahead) and statuses via `update_surge_status` at `t`; an attribution is
  attached only from a stored surge on the same exchange and direction whose `detected_at` lies
  within the detection's window and whose `attribution.analyzed_at <= t`. Never use a stored
  surge's later fields (peak, status, current price).
* High bands: `analytics.high_band(series <= t, t, ...)`.
* Fair values (`use_fair_values`): per exchange the newest record with `ts <= t - latency_s`,
  rebuilt into a `FairValue` (`usable` and `as_of = ts`).
* Settlements with `settled_on <= t`; leaderboard snapshots with `at <= t` (bar via
  `sizing.estimate_bar`); `infos` = `source.exchanges()` filtered to outcomes with a quote at `t`.
* `GuardedHistory` raises `LookAheadError` for any read whose `until` (or `since`) is after `t`
  or that omits `until`. Tests prove it is never raised by a correct run and is raised by a
  deliberately wrong adapter call.

#### 6.12.3 Assumptions, coverage, sweeps

* `assumptions` always lists, with the configured numbers: the decision grid and latency; how
  quotes, depth and passive fills were synthesised where history lacked them; that fair values
  replay only what was recorded live; that the tape is sparse (the tracker stores trades only
  for surging outcomes); that attribution verdicts are used only once analysed.
* `coverage`: exchanges, decision steps, and the share of (exchange, step) pairs whose quote
  came from ticks vs candles, of fills from book snapshots vs synthetic books, of steps with a
  usable fair value, and of maker fills from the tape vs candles.
* `warnings`: "Only N hours of data" (< 12 h), "Most quotes are candle-based: spreads and depth
  are assumptions" (candle share > 50%), "No fair values were recorded in this window: value
  ideas could not trade".
* `parse_sweep(["min_value_edge=0.01,0.02", "latency_s=30,60"])`; values parsed as int, float,
  bool or string; names looked up in `StrategyParams`, then `BacktestConfig`, then
  `PaperConfig`; unknown name -> ValueError listing the valid ones.
* `sweep(source, base, grid)`: Cartesian product, at most 50 runs (else ValueError); returns the
  base run's report with `sweep` rows `{"params": {...}, "label": "min_value_edge=0.01,
  latency_s=30", "pnl_liq", "trades_closed", "verdict_level", "max_drawdown"}` for the
  headline portfolio, sorted by `pnl_liq` desc, and `SWEEP_WARNING` in `warnings`.

### 6.13 Tests (`tests/test_paper.py`, `tests/test_backtest.py`)

Use hand-built observations, `MemoryPaperPersistence`, fake policies (e.g. a fixed-units policy)
and fake signal functions; plus one test with the real `sizing` and `strategy` once they exist.

1. Taker: a book observed before the decision (or within `min_latency_s`) never fills; the
   first eligible book is used even if a later one is better; depth walking and limit; partial
   fill + IOC reason; consumed liquidity is not re-used on the next order and is forgotten after
   900 s; stale quote blocks; expiry after `max_fill_delay_s`.
2. Maker: trade-through fills at the limit, capped by size; at-price prints after the queue with
   the haircut; unknown queue -> only trade-throughs; prints before placement ignored; dedup by id;
   expiry; cancel after 2 missing steps; failed tape read -> no fill.
3. Sets: both legs fill; legging residue exits and records a "legging" trade; basket exit by set
   proceeds; settlement of every leg.
4. Exits: each rule and the order of precedence; dynamic fair-value target; one exit order only.
5. Settlement 1/0 for YES and NO, refund, `payout_yes None` -> frozen; frozen on closure without
   a ruling; Cup end freezes trading.
6. Valuation: liquidation walks depth (shares beyond depth worth 0), touch fallback flags
   `depth_unknown`, inconsistent book ignored, mid and fv references, drawdown.
7. Accounting: reservations; free cash never negative; cash never negative; all-collateral
   advance and repayment; realized vs unrealized; trades and per-day profit.
8. Portfolios: independence (two portfolios hit the same book independently); kind filters;
   one net position per exchange; cooldown; caps on positions and new orders.
9. Verdict: each level with constructed trades; exact sentence templates; bootstrap determinism
   and clustering (10 trades in one race = 1 cluster); Wilson interval.
10. Persistence: save, construct a new engine on the same persistence -> continues with the same
    state; reset ends the run with "reset" trades and starts a new one; final snapshot at 24 h.
11. Runner: read priorities; never more than 8 books / 2 tapes per step or the limiter's room;
    `skipped` counted; a spy reader proves only `book` and `trades` are called; decisions use
    `decided_at` after reads.
12. Summary JSON: every key of §10.1 present with the right types; limits (300 equity points,
    100 fills, ...).
13. Backtest: decision grid; a source that would leak future data trips `LookAheadError`;
    candle-only history produces synthetic quotes/books and the assumptions say so; book
    snapshots used for fills when present; fair-value latency; surges attributed only after
    `analyzed_at`; the same `PaperEngine` class is used (monkeypatch spy); sweep grid, limit
    and warning; report shape.

## 9. Read budget (Super Market: 100 reads/min per account, client cap 90/min)

Live Cup: 237 binary markets, 237 outcomes, 30-s interval.

| consumer | reads | per minute |
|---|---|---|
| bulk prices | ceil(237/100) = 3 per cycle | 6.0 |
| market list | 3 per 300 s (+ early refreshes while outcomes settle) | 0.6 (+ up to 2) |
| context | constraints 1 + tournament 1 + pnl 1 + leaderboard(100) 1 + idea books <= 12 (+ overround: 0, the Cup has no multi-outcome markets) per 300 s | <= 3.2 |
| settlements | ceil(settled/100) per 600 s (usually 1) | 0.1-0.3 |
| backfill | 474 reads at <= 30/min in the first ~16 min, then 0 | 30 -> 0 |
| analysis | ~2 per new or grown surge, limiter 20/min | ~2 (bursts <= 20) |
| dashboard drawer | 1 book per open drawer per 15 s | <= 4 |
| **paper** | <= 8 books + 2 tapes per step, limiter 20/min | **<= 20** |
| **total, steady** | | **~36** |
| **total, worst case at start-up** | 6.6 + 30 + 20 + 3.2 + 0.3 + 4 + 20 | **~84 <= 90** |

## 13. Known unknowns (do not resolve them by guessing in code)

* The Cup's end-settlement regime (`resolved_outcomes` vs a 5-hour VWAP closeout): exposed as
  the `--regime` option, default `unknown` (conservative).
* Whether D/R pairs are linked by ALL relationships (collateral savings): `--all-collateral`
  is off by default.
* Each market's resolution source (media call vs certification): `called_prob` is a documented
  heuristic.
* How the mid-Cup leaderboard values are computed: the bar estimate says they are marks.
* Live Polymarket/Kalshi reachability: this sandbox cannot reach them; the user's machine can.
  The code must degrade to "no outside fair value" and say so.
* Pins come from other participants' public files: validated live before use.
